# 跨小时受限恢复

此入口与原 Q03 恢复工具并存，不修改原入口。仅支持本次已验证的 Linux、HiGHS 1.15.1 场景：导入 Q00–07 的完整独立备份，继续 Q08–11，新增一个小时结算。它不是任意时点、任意机器恢复工具。

## 两阶段执行

1. 用 `python -m gd_restore_crosshour_runtime preflight` 核对固定配置、源码、历史八格和外存回执。复核该报告后才运行同模块 `run`，显式指定配置及预检 SHA。每格执行后等待独立 Library 下载核验回执；无回执不继续。四格共 12 次优化调用。
2. 调度完成不等于经济结果验收完成。原运行固定的旧经济读取器可能因历史调频回执位置改变而缺少估算。用 `python -m gd_restore_crosshour_runtime.replay_economics --config ... --config-sha ...` 对新 H2 单独派生经济结果。该命令启动受保护的独立 Python 进程，禁止优化调用，仅加载已独立审查的读取器，不覆盖原 HOUR、EXECUTION、SETTLEMENT。
3. 将派生结果、DERIVATION 和 PYTHON_GUARD.jsonl 三文件打包存到工作区之外，并重新下载比对。随后用 `python -m gd_restore_crosshour_runtime.complete_economics --output ... --archive ... --ack ... --ack-sha ... --config ... --config-sha ...` 核对下载归档、源码和原始输入，再以新进程零求解重新派生并逐字段比较结果，生成独立的 ECONOMICS_COMPLETE。

没有 ECONOMICS_COMPLETE 时，派生结果只是已计算，不算可靠保存或完整验收。派生失败仅重做派生，不重新跑已完成的四格调度。程序不会自行上传 Library，需要外部协调器。

## 完成门防误报

运行配置必须显式绑定。经济重放要求整个安装 app 下的 Python 源码递归固定 SHA，并检查本恢复包源码；防止只给 bridge 文件而漏掉其依赖。禁用已有字节码缓存。配置缺失、空源码列表、依赖变化、归档成员缺失、守护进程记录不完整、结果重算不一致均拒绝完成。自述“已通过”不能替代重算。

Python 守护记录只证明本次 Python 进程检查范围，不是操作系统级或原生库级全访问审计。独立 Library 回执由外部协调器提供，CLI 对下载字节核对，不自称具备 Library 服务端鉴权。
