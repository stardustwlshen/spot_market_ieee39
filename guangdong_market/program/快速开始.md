# 广东省内电力市场研究程序：快速开始

这是研究程序，不是实际调度、正式市场发布或计量结算系统。正式安全放行始终独立；数学求解成功不等于安全通过。

## 1. 安装与启动

在解压后的程序根目录（可看到 `requirements.txt`、`app/`、`engines/`）执行：

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m streamlit run app/主页.py --server.address 127.0.0.1
```

推荐 Python 3.12 / Linux，浏览器打开终端给出的本机地址。保留终端运行，不要公开无鉴权服务。Mac/Windows未完成实机验收。依赖安装需要网络；第一次安装不等于已经求解。

## 2. 保存场景并选择日前来源

1. 在主页场景编辑器修改负荷、风光或报价，点击 **“校验并另存新版本”**。新模型读取保存后的场景；侧栏旧CSV边界/旧全链按钮不是新接口。
2. 有已接受日前结果时直接选择其目录，无须重新求解。编辑了场景或报价则必须为新版本建立新的日前来源，不能沿用旧来源假称重算。
3. 没有对应已接受来源时，使用 **“独立准备/求解日前（不运行旧RT）”**：填写全新输出目录，先预检和准备（0求解），再明确确认最多3次优化：SCUC、SCED、独立DA PRICE。实际量和独立价格均验收后，点击 **“选此已接受DA进入下方统一实时入口”**。这一步不运行旧RT，也不等于完成正式DA98时序发布。
4. 在 **“修正循环尾约束的研究开发入口”** 选择上述已接受DA，填写新研究目录/名称及明确的 `+08:00` 可用时刻。阅读初态、合成数据和首15分钟已下发假设，确认后点 **“1 准备新研究（0求解）”**。

切换场景、DA、运行目录或选项后重新查看计划并确认。不要覆盖旧输出或手改 `code_pins`。

## 3. 推荐先完成一个研究小时

进入 **“同一新分支：实时 + 小时调频 + 独立定价/核算”**：

1. 保持 **4窗**，使用未用过的会话名。
2. 对符合五个合格独立电厂各10 MW、总50 MW条件的场景，选择 **“SCUC后调频：五机饱和规划研究”**。不适用的场景应停止预检，不擅自修改资格或容量。
3. 为完成连续研究计算，明确勾选 **“系统安全未验证或失败时仍允许继续反事实研究计算，保留blocked状态、不发布”**。首次推荐不勾AC或损耗纠正。
4. 点 **“查看完整预算/来源计划（0求解）”**，核对同一DA/case及最多12次优化，确认后 **“启动同一新分支一次”**。
5. 用 **“读取同一分支进度/价格/小时（0求解）”** 更新进度，完成后查看H0价格与54行研究电能量核算。最终6720正常入口已真实完成一次12次HiGHS、0AC、4窗/4价/H0 54行（含有限H1）。与主全天并行约370秒，不是独占性能基准，也不保证任意编辑场景可行或固定耗时。

**如果没有勾选反事实继续，程序默认会在安全未放行时于handoff之前阻断。这是安全门生效，不是页面挂住。** 反事实继续不把失败变为安全通过，也不授权真实调度。

### 单独选择有限候选H1

首小时另可勾选“有限候选H1研究模式”，同时保留五机规划。该选项仅适用于现已验证原c10e库存、原需求50和双400，仍最多12次优化。W0/W1沿原规划；H1真实数据到00:30才进入当期有限choice模型，实际分配接受后由W3消费。既有独立干净12次真实算例之外，最终6720正常用户入口也已完成一次12次整合实测，真实H1接受回执由后窗消费。不是不同库存或全天通用；禁止与96、classic参考修订、损耗诊断组合。默认关闭，改动选项须重新确认。

### 时间分辨率与研究时钟

当前研究模型以5分钟为功率、状态与执行格分辨率；滚动优化每15分钟交接一次3个5分钟格，不是每5分钟重新优化。当前截止时点到新计划域起点之间的3格是既有已下发前缀；新计划域从15分钟后开始，向前覆盖4小时；4窗对应一小时的12格研究执行。这里的“执行/下发”均为无偏差研究模拟，不是实际电网指令。

## 4. 四种运行模式不要混用

以下是优化上限，不含已完成DA、不含另选AC/损耗纠正或独立未来基点调整。默认不执行任何调用。

|模式|最大优化预算|调频/跨日关键时刻与范围|
|---|---:|---|
|首小时4窗（可选五机post-SCUC规划）|12＝4 SCUC＋4 SCED＋4 PRICE|模拟执行12格，另3格已下发但不计入H0；规划不是已接受回执。有限H1仅4窗；全天须另选专用post96，不能直接沿用首小时开关。|
|原参考96窗|288＝96 SCUC＋96 SCED＋96 PRICE|独立D+1声明须预先选择；原路H24于W93可用后、W94前消费。已知DA/AGC价格界不兼容会启动前拒绝，不能承诺完整96价。|
|classic289：原路D+1参考修订|289＝288＋1参考SCED|同运行W93接受后、W94准备前生成研究参考；q95只替换声明范围内的D+1热机参考。不是post96，不能混选。|
|post96：SCUC后调频＋接受后D1参考|289＝288＋1参考SCED|逐小时SCUC后内部调频再SCED；H24须W94完整接受及衔接后，23:45才可用（数据时点23:30），再参考SCED、q95定价。H25不自动续50。|

96模式必须创建/选择同run、DA、case、日期及资格绑定的命名D+1研究声明。登记声明不是提前发布；预算也不是预计耗时。post96同来源显式接续全天已通过最终只读审查：96窗/96价/24小时。所选链289次，实际成功290次加1次超时共291次优化，另有1次零优化loader失败，总292 worker发生次；失败原件保留。不是未中断的原UI运行，也不保证新场景成功。

RT的SCUC/SCED/PRICE时限分别300/120/60秒，单线程，SCUC gap为0.1%。日前入口时限600/120/120秒；参考SCED120秒。严格验收失败或未知即停，不自动切算法或重试。全天校核仍有较重的来源文件IO；新SHA缓存仅证明热哈希扫描收益，不代表整窗或端到端等比例加速。

## 5. 单独走安全诊断路径

诊断时**不要勾反事实继续**。可选择W0候选首5分钟点一次AC；它在handoff前运行，不是全天安全检查。

若另外明确选择 **“同候选损耗纠正诊断”**：
- 必须同时授权首次AC；当前仅原c10e、AGC50、双400研究条件，编辑后不支持的case在预检拒绝。
- 最多额外1次SCED＋1次AC；4窗完整计划上限变为13次HiGHS＋2次AC，不代表会用尽。
- 已实测W0拒绝链为 **4次HiGHS＋2次AC**：seed PRICE、原SCUC/SCED、纠正SCED；不重复SCUC。纠正后C1越限消失，但仍有10个电压越限及约0.337 MW偏差，因此handoff=0，无W1、无HOUR。
- 页面分列原候选、纠正候选及两轮AC，保留失败。即使第二AC局部改善，其他安全检查未完成也继续隔离；这不是完整安全纠正闭环。

研究启停模拟、事件PRICE映射、反事实继续、AC及纠正是独立选择。停机保护例外还需要单独来源/时刻/曲线声明；不能凭启停checkbox解除AGC资格限制。非零启停的独立“所选DA最后48格研究边界”最多3次优化，不是默认50链或已执行小时。

## 6. 读取结果、缺项和停止

- **新运行**只读取同一run的价格、功率、SOC、内部调频回执和小时结果。12执行格之外的额外3下发格不计入该小时。
- **固定示例快照**不随当前场景/报价编辑重算。原缺价分支、独立修订参考全天分支、同来源显式接续全天和最终6720正常首小时分别选择；原01ab UI曾失败，接续结果不能伪装成原UI一次成功；注册历史只能显示，不能恢复livehost或授予新调度权限。
- 缺一季度价格就不能给完整小时金额，不补0；不能用旧base或另一个分支的价格填空。已完成小时先保存，未来价格失败不抹掉已有小时。
- 分项输入格式见 `app/gd_settlement_runtime/INPUT_SCHEMA.md`。合约、资格、计量、补偿等未知只阻相应分项，未知合同不等于空合同。**“模型列示账户电能量分项净合计（研究）”不是市场总额、利润或正式净账单。** 储能充/放/净金额可跨正负。
- 工作目录中保留 `PLAN.json`、`EXIT.json`、`pipeline/` 与阶段raw；安全门的 `BEFORE_HANDOFF.json` 和纠正结果不被覆盖。失败/未知不要换名盲目重跑，先核进程与已完成调用。关闭网页不等于取消后台；进程退出后不能用JSON恢复信任身份。
- 版本改变导致旧live来源门禁拒绝时，使用明确注册的历史快照，不删除门禁。正式DA98申报/发布时间证据、完整实际账单及新调频规则实施细节仍有缺口，不能从研究通过推断正式合规。

## 未来RT SCED数值策略与校核缓存
新worker未来RT SCED默认显式单次HiGHS IPM+crossover，primal/dual可行性1e-10，IPM内部收敛目标1e-10；不改变模型、原KKT门限或调用上限，不是失败后的自动fallback。SCUC、PRICE和独立reference不因此改变。损耗纠正仍只允许其已声明的额外一次SCED/AC。新策略已有独立W54同LP一次真实成功证据（内部目标由1e-12改1e-10，最终KKT门限不变）；最终6720正常用户入口已用一次新12次HiGHS覆盖此策略、memo及有限H1消费者，0AC、无重试；这不是重算旧12次/4+2证据。其后只读卡仅展示已保存结果，不代表显示代码修改后又进行了数学验收或求解。

数学memo已由上述最终正常入口实测覆盖；仅在一个正常native worker的同一session激活，首次完整核验，后续压缩完整payload逐字节相等才复用；不信任JSON passed、不支持恢复，源码或注册来源变化仍拒绝。它只减少重复校核与IO，不保证端到端提速倍数。
