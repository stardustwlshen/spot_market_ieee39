# Same-run SafetySession incremental API
Install only files named in SOURCE_MANIFEST.json plus safety_gate.py and this note into one new application module directory. Add that directory to sys.path. Import `from safety_session import SafetySession, plan`. The installer must pin safety_gate.py and SOURCE_MANIFEST.json in its own source manifest. No source/inputs from sibling research directories are runtime dependencies.

Usage: construct once per live host; call inspect(w) after host accepted_pair. This reruns strict pair checks, records model balance/reserve/SOC as mathematics only, retains unknown operating checks. `run_ac(w,new_output,execute_ac=True)` is optional, defaults to no action and has maximum one AC call per session; UI should restrict to W0 first domain point (00:15 under this branch), not seed00:00. Only original IEEE39 grid/five-thermal/storage capabilities and original Q0/benchmark load Q/P research proxy are supported. Signature changes reject, not silently fill data. Native AC runtime uses the unchanged supplied ac_security.py and installed PYPOWER/numpy; no HiGHS call, Q/V optimization or added capability.

`reuse_known_W0()` is NEVER automatic. It requires actual branch UUID and complete payload/AC-input/result-input identity against fixed trusted included evidence. New scenarios cannot borrow historical failure/pass. `inspect` alone never reads this evidence.

Failure opens a same-run failure-workflow state. `propose_reclear(w,proposal,declaration_path=...)` requires the exact same-run proposal file already registered in host source_pins. No declaration => blocked; self-asserted JSON/hash does not authorize. Workflow preserves 50MW, 400/400 and original awards/qualification; unknown unit attribution cannot remove awards. `reclear_request(w)` only returns a research request when the declared proposal passes workflow prerequisites. It does not execute an optimizer; runner integration and new accepted raw + new safety recheck remain required. No automatic publication path exists.

`allow_counterfactual_research(explicit=True)` permits an explicit research-only choice, never a safety pass or dispatch authorization. Runner must decide whether to continue blocked counterfactual calculations; it must keep blocked visible. `require_safe_publication()` always refuses in this bounded research implementation.

Tests: TEST_RESULT.json exercised actual fixed-source live host, same-input prior AC reuse, failure workflow opening, missing declaration and cross-branch refusal. SUPPORTED_TEST.json verifies complete regenerated payload/AC-input identity, package integrity and rejection signature for capability edits. Both 0 new AC/optimization. Original raw AC evidence contains one previously completed call, not newly run here.

`plan_reclear(w, runner)` calls only a code-registered runner.plan_reclear(request), same host identity required. Callback must return pending_authorization/blocked, matching branch/candidate, actual_native_calls=0 and actual_AC_calls=0. Runner module must be in host source_pins. CALLBACK_FIXTURE_TEST verifies failure→missing declaration→registered fixture declaration→request→same-host pending plan, never actual re-clearing.
