# 独立检查点恢复：限定范围

本次新增独立命令行入口，不修改市场模型和常规出清流程。原备份和原运行目录不改写。

当前只支持 Linux、HiGHS 1.15.1、省级15分钟、原始96格单日任务、Q00–Q03完整已备份且H0已结算、无实际启停事件的前缀，恢复后仅执行Q04、Q05。它不是任意时刻、跨机器、跨平台的自动恢复功能。

启动前必须重新核对归档字节、代码和输入来源、完整依赖及状态连续性；不能凭“passed”字段跳过验证。未知格式、缺依赖、混合运行、不同版本、篡改、未来格、重复输出目录一律拒绝。代码及日前baseline安装仍需可访问且与归档逐项匹配。

每个新格必须等待独立外存下载验真ACK；不能将本地另一个文件夹当外部备份。原H0账目只导入一次，不重新结算。所有新求解有独立attempt标识。

Python主进程和worker启用读取保护。环境不支持ptrace时，不能声称OS级原生系统调用已跟踪。本版本尚未证明跨小时新增结算或全套依赖迁移到新电脑。

## 命令

在程序目录运行（先确保 `app` 位于 Python 模块搜索路径）：

```
PYTHONPATH=app python -m gd_restore_runtime preflight --config 恢复配置.json --config-sha 配置SHA256 --report 恢复预检.json
PYTHONPATH=app python -m gd_restore_runtime run --config 恢复配置.json --config-sha 配置SHA256 --report 恢复预检.json --preflight-sha 预检SHA256
```

配置只能指定已验证归档、固定依赖清单、原始安装及新输出位置，不能指定额外时段或修改市场参数。`run` 会再次执行完整预检并创建不可复用的运行锁。失败后保留目录，不自动重试；不得删锁后在同目录覆盖。

当前仍要求独立外存协调器运行。没有协调器时不可启动，不能取消ACK等待来“恢复”。这一版面向受控的修复验证，不在正常网页中提供“任意时刻恢复”按钮。

## 先盘点最后连续备份（只读）

新增 `python -m gd_restore_runtime.inspect_backups --catalog 备份清单.json --catalog-sha 清单SHA256 --report 盘点报告.json`。

清单格式为 `{"schema":"gd.backup.catalog.v1","quarters":[...]}`。每一格按 Q00 起顺序列出 `archive`、`receipt`、`receipt_sha256` 三个字段；尚未取得独立下载验真回执的位置填 `null`。最多96格。

盘点会重新读取归档及回执，验证所有有效载荷的大小与SHA。遇到首个缺格、缺回执、篡改、时标错误或原输出目录不一致时停止；后面的归档不会跨过断点提升连续进度。报告中的分钟数是模拟时刻，不是计算耗时。

这一步只证明独立保存的字节及连续目录/时标匹配，不证明同一路径从未复用、不证明完整依赖或模型已验算，更不自动授予续算权限。`computed_progress` 和 `model_validation_progress` 保持未知；`resume_ready` 始终为 false。现有受限恢复入口仍须另行执行全部门禁。报告使用新文件独占创建，不覆盖旧证据。
