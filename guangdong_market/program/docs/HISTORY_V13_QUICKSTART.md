# v13快速开始

## 1. 安装并启动

在解压后的源码根目录运行：

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python -m streamlit run app/主页.py --server.address 127.0.0.1
```

使用Linux/Python3.12。Mac未实机验证，Windows批运行不支持/新live入口未验收。服务只绑定本机，不直接公开无鉴权应用。

## 2. 准备自己的日前与RT输入

1. 在广东省内主页保留的场景/报价编辑入口另存研究场景，运行日前并等待严格接受。
2. 打开“修正循环尾约束的研究开发入口（统一实时/定价/核算）”。使用上方已接受日前目录，或选择另一个已接受来源。
3. 填写新研究运行名、存储位置和明确假设的可用时刻；勾选保守保护/合成次日声明/首15分钟已下发初态，点击“1 准备新研究（0求解）”。
4. 旧安装生成的RT run不能直接迁移为本安装新运行：code_pins与安装位置绑定，应从同一已接受DA重新纯准备，不改写旧接受记录。

## 3. 使用同一新分支首小时流程

回到新卡“同一新分支：4窗实时 + 小时调频 + 4季度定价 + 首小时核算”：

1. 输入一个从未使用的会话名。
2. 点击“查看完整12调用计划（0求解）”，核对DA/run、研究参数与预算。
3. 明确勾选授权后，点击“启动同一新分支一次”。将使用4次SCUC、4次simplex SCED、4次独立PRICE，最后做H0核算。
4. 点击“读取同一分支进度/价格/小时（0求解）”。四季度价与54行核算均显示在此新卡；不要将下方旧base逐步入口的结果当作它的结果。

默认不求解。各次300/120/60秒为原生时限，不是预计用时。缺价不补0；任何失败或未知会保留证据并停止后续阶段，不自动重试或切换策略。不支持断点恢复；关网页不等于停止后台。

## 4. 正确理解结果

- 首小时只计12个5分钟执行格，额外3个已下发格不计入。
- 数学接受、系统安全、正式发布分开显示；本版不放行真实调度。
- 真实四窗/4PRICE核算已在前一阶段验证；v11的通用输入、界面和历史兼容测试为0新增求解，未再次从本按钮跑满12次。
- 新通用96窗/H24、AC完整校验仍未完成；固定新分支00:15点已有AC限额失败证据，不作其他新场景的结论。
- live API通用化不等于任意启停工况可用：仅稳定/离线初态与已声明固定研究曲线，初始active event导入未支持；真实IEEE39非零启停未验证。启停已接worker，需独立显式许可研究模拟指令；缺必要指令回执仍拒绝。
- 旧v9 96窗入口/历史日只供其自己的独立研究结果使用，不代表新live流程已完成全天。

## v13新增选项

启动前先阅读README的“v13新增操作与准确验证边界”。四个独立研究选项默认关闭。默认遇安全未放行暂停，若要继续首小时研究计算必须另选反事实继续并保留blocked。未来cap入口采用两次确认且与主计划分开，不能修复原失败点。
