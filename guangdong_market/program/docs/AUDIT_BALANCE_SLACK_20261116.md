# 供需松弛异常小时处理

基于 main 545872d。原先包含供需松弛的小时在结算时中断后续滚动；本次不改变调度模型和罚值。

- 仅当原始供需残差与明确的缺额/过剩松弛量一致时，保留调度、价格及诊断，并标记经济结果不可用。
- 异常小时不生成收入或利润，不把缺失当成零；累计完整收益被阻止，仍可查看正常小时。
- 下一小时允许继续执行；无法由松弛解释的不平衡、非有限值和来源错误仍抛出，不吞异常。
- 保留第一批运行中断提示、AGC实际优先、线路及末状态偏差提示。

验证通过：缺额/过剩/同额抵消/未知不平衡/非有限数拒绝；异常后正常小时继续；AGC与运行状态回归；368个app模块语法检查。

加强联测使用真实导入的 PriceSession.hour、实际文件与子进程、HiGHS微型供需优化，验证H0缺10MW时金额为空且无结算文件，H1无缺额继续结算，真实结算导入拒绝异常小时。快照与报价来源为测试替身，小时计算使用微型模型；不是完整省级日前、实时调度和定价原生链验证，未重新运行全天或跨平台实机。
