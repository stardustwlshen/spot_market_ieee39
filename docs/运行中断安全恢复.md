# 运行中断与安全恢复

机器重启后，旧运行不再有可工作的后台进程，但不能仅按 PID、主机名或变化的启动时间判断：项目可能来自另一台机器，PID也可能已复用。普通状态检查继续保守地保留未知占用。

## 网页操作

在“单机报价模拟”下方选择对应运行，查看“运行中断与安全恢复”。只有程序核验原进程已不存在时才显示恢复按钮。勾选保留历史并标记中断后，再点击“确认进程已不存在并恢复”。

恢复将该次运行标记为“失败 / 已核验中断（非完成）”，解除这条记录的占用。全部其他运行仍独立核验，存在任何活动或未知记录时仍不能启动。取消请求保留，恢复后不会继续显示取消等待。之后可继续改价、修改机组或创建另一运行。

不强杀进程、不重算、不生成结算。原日志、实时已执行前缀、日前结果、报价、成本、冻结快照和其他输出保持原字节。中断不等于完整日完成；已有部分输出不作为已确认完整日结算。审计信息与原始元数据一起保存在该记录的新 meta.json 的 recovery 字段中，包含旧记录、核验依据、UTC操作时间与原记录摘要。

## 核验边界

- 新进程身份增加带来源/版本的系统机器标识摘要：Linux `/etc/machine-id`、macOS `IOPlatformUUID`、Windows `MachineGuid`。只存摘要，不存原始系统标识，不在项目目录生成可随复制传播的“机器身份”。
- 跨重启恢复还必须有不同的可信系统启动会话标识（Linux内核 boot_id、macOS kern.bootsessionuuid）、一致的机器身份/主机名/系统、严格前进的启动时间和早于本次启动的原进程创建时间。启动时间变化或时钟调整本身不是死亡证据。
- Windows当前没有已验证的系统启动会话来源，因此**重启后仍保守保留占用**，不使用时间或注册表猜测代替。Windows同一次启动内的PID、创建时间核验仍可用。
- 克隆系统、克隆硬件UUID、重复或共享机器ID不在可信环境范围内。仅靠软件读到的相同系统ID不能证明是同一台物理机器；这类部署不要使用恢复入口，应请管理员核验原服务。此功能不是远程证明或分布式锁服务。
- 其他机器、权限不足、损坏/缺失身份、当前仍存活的进程、不一致启动证据均不能恢复。
- 启动器在同一次启动内退出，不证明其后台子进程退出。只有确定是本机前次系统启动的完整身份，才允许启动器证据用于恢复“子进程身份尚未来得及落盘”的记录。

## 升级前旧记录

升级不会补写或推断历史机器身份。同一次系统启动内，缺少机器身份的旧记录也保守视为未知，不再只凭主机名与接近的启动时间判死；这是为共享项目安全所作的兼容性取舍。没有稳定机器身份的旧记录（包括之前版本已重启的记录）仍然无法由本机程序证实死亡，界面会显示具体缺少的证据，不能直接点击恢复。

请先保留原目录，在原运行机器核对并正常停止原后台服务；不能通过修改PID、状态或删除运行目录解锁。无法取得原机器证据时，由管理员确认所有原服务已停止后，可由用户另建不继承旧 `runs/` 记录的独立项目副本继续使用，并保留原项目及全部历史文件。单纯复制整个项目和旧活动记录会继续保留占用，不会解决问题。该人工处理不是本程序对旧运行死亡的判定，应用不会自动执行。

## 并发与失败保护

恢复与启动使用同一项目启动锁，再取得该次运行的元数据锁，锁内重新读取并核对页面所见记录的摘要，重新检查全部已有worker身份。记录被新进程修改或已经完成时不会覆盖。路径须属于当前项目运行根目录，不能经目录链接写到外部。审计和终态在一次原子替换中提交；写入失败保留占用，重复成功点击幂等。未修改任何市场参数、求解器、成本政策或备用规则。

验证范围：Linux实际进程、跨进程锁、Streamlit实际页面AppTest；macOS/Windows身份读取为模拟分支测试，不声称原生平台验收。
