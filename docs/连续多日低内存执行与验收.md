# 连续多日低内存执行与验收

## 适用范围

本实现只调整已完成求解对象的保存时间，不改市场数学、输入、逐日报价、约束、优化窗口、预测算法或随机样本。多日仍按日顺序运行：前一日真实末态进入下一日的 DA、ID 和 RT，不是现实 D−1 发布流程，也不是联合多日优化。

曾有默认 IEEE39 双日进程在首日全部 RT/ID 求解日志结束后以 exit 137 退出，未产生 day_commit。退出时另一套完整测试并行运行，缺少可靠 OOM 日志，因此根因尚未确认。求解日志结束不代表当日归档和接续提交成功。后续默认规模验收应与全套测试串行，不能把本次微型验收代替该规模验证。

## 正式入口和兼容 API

- 正式多日 UI/CLI worker（`smm.series_ui_runner`）显式调用 `run_series(..., result_retention='archive_only')`。日提交后返回目录、commit/checkpoint 哈希引用，`new_results` 为空；不累积各日完整求解对象。
- 正式单日 CLI/旧运行页 worker（`main_full.py`、`run_scenario.py`）以及相关批量/比较/示例脚本显式选择 `retain_id_models=False`。
- 库函数调试兼容不变：`run_full`、`run_rolling` 的 `retain_id_models=True`，`run_series` 的 `result_retention='full_debug'` 仍是默认值。调试调用者若保存返回对象，仍会保留模型。
- 正式低内存路径不仅增加一个标签：真实验收检查进入 `run_full` 的参数、每个 ID 的模型字段、下一日前的弱引用，以及提交后的模型回收。
- 已提交日期恢复只验证冻结文件和哈希，不重复求解或覆盖旧日结果；未提交目录仍禁止默默重跑。本改动没有扩大到任意 RT 中段恢复。

## 何时释放，保留什么

成功 ID 的正式电能 SCED 对偶读取为 float64 数值证据。先保存阶段输出、辅助定价证据、水量选择证书和状态价值，再完成参考合并，才从历史记录移除 `model`/`pricing_model`。RT 历史本来就只保存数值结果，不需保留 RT 模型。

缓存分别保留原有两个消费者的语义：参考交接允许逐资源缺值并按配置回退；严格水电审计在原读取失败时仍返回 None 或抛出原类别异常。不得把合法部分错误改成一律失败，也不得在缓存缺失时重新求值、重定价或悄悄回退。两次成功读取必须来自同一未变 SCED 对偶，全部值和元数据精确相同且没有错误记录。

当前缓存 schema 为 2，契约为 numeric_ID_evidence_v2。即使 strict 为 None，仍对成功资源逐数组核验 native = -dual_raw[1:]、末段为 0，以及原单位换算。因子分别为 E:1、Vu:1/e_gen、V:0.36×water_rate，从原正式 SCED 模型参数捕获；summary 中 id_state_value_parameters 另由本日有效配置生成独立参数锚。正式离线检查拒绝仅篡改 sidecar 因子并重算数组/哈希的记录。这是数值和独立资料一致性验证，不是对同时篡改全部根资料的签名认证，也不重新构建 KKT。

新归档包含 `id_state_value_evidence.json`。紧凑模式的 `summary.json` 声明 `id_result_retention` 契约。正式 `scripts/validate_runs.py` 对声明的新契约核验：字段/时钟类型、哈希、轮次完整性、剩余日覆盖、快照资源集合、逐资源错误、同源缓存一致性，以及原水电审计证据中的严格状态价值。缺档、无解释缺资源或重算哈希后的相互矛盾均不通过。

无声明且无 sidecar 的旧归档维持旧审计范围，不被标成已通过新数值缓存验证。多日 day_commit 另对全部归档文件提供哈希完整性约束。

每个正式系列日完成输出、检查点、现金成本证据和 day_commit 后，删除完整 result/case，再调用 GC，最后写 `day_committed_models_released` 阶段。`run_phase.json` 是最新阶段定位信息，不是全阶段历史；RSS 在支持的平台记录，不支持时为空。文件完整性哈希改用固定大小块读取，哈希结果不变。

## 已验证的相等范围

1. **同一个已求解结果**：微型两母线、4 个已执行小时、2 轮 ID、开启辅助定价。全模型和紧凑路径比较原有 69 个归档文件：66 个字节相同；summary、输出清单和索引只有明确新增契约/sidecar 元数据差异。所有原有数值、物理轨迹、价格、对偶和审计值相同。未删除非唯一整数轨迹来制造相等。
2. **真实两日接续**：微型两母线、每天 24×1 小时和 4 轮 ID。逐日冻结报价独立；真实末状态接续；热电持续时间、水电逐台义务/梯级水量、储能、抽蓄切换、实际现金和成本独立重放。日前模型在下一日前无存活弱引用，提交后完整模型均可回收，恢复不再求解。这不是默认 IEEE39 双日。
3. **完整 spot 利润**：另一个显式成本齐全的六主体真实两日 archive_only 用例，288 条不重叠实际主体时段。逐日不同成本哈希，独立核算燃料、在线、启停和净现金，逐日及系列误差为 0。该人工成本例现金 40900 元、成本 32996.333333 元、模拟经营利润 7903.666667 元，不代表真实项目收益。缺 H2 成本的另一用例仍输出成本/利润未知，不补 0。
4. **因果输入和水电后缀**：15 分钟日模型，实际只执行两段；真实可变天然来水、同 issue 日末包、活动日电量后缀、辅助定价和事后误差输出均通过紧凑归档。不能称为完整因果两日验证。
5. **非零值与反例**：另有真实 Pyomo suffix 的正负非零读取、单位/移位/终态值、部分缺失和原异常语义，以及缺档、来源、资源、时钟、哈希、两份同源值冲突等反例。缓存异常必须阻断相应审计。

## 内存证据及限制

- 早期微型探针中，4 轮 ID 保留 8 个模型。冻结数值后删除这 8 个模型，GC 后仅剩 DA 两模型，Python 活跃内存减少约 17 MiB，原 full.checks 相同。
- 31 日压力测试**没有求解器、物理接续或现金计算**，使用显式 stub 和每天固定 8 MiB 对象，只隔离测试编排是否保留完整日结果。调试模式存活对象随天数增至 31；archive_only 在每个下一日前为 0，RSS 基本稳定。它不是 31 日出清验收，也不证明所有输入/轻量数值/预测注册表内存与天数无关。
- 单日 DA、当轮模型、数值结果和系列预测数据仍需要内存。本次没有改为流式大 JSON，也没有证明默认规模导出峰值已经足够低；需结合正式串行大算例的阶段记录继续核验。
- 独立两次 MIP 可能因 gap、时限或非唯一性得到不同整数解。释放模型的数值等价以同解比较为主；微型真实两日额外记录实际 gap，不以重新求解结果的巧合代替同解证明。

## 回归入口

安装项目既定依赖后运行：

```sh
PYTHONPATH=src:tests:app:scripts python -m pytest -q \
  tests/test_result_retention.py tests/test_retention_offline.py \
  tests/test_retention_real_evidence.py tests/test_retention_series.py \
  tests/test_retention_causal.py tests/test_retention_complete_costs.py \
  tests/test_retention_value_math.py tests/test_retention_numpy_parameters.py
```

再运行阶段交接、失败恢复、完整项目测试和串行默认规模双日。 focused tests 不代表整套通过；正式交付报告保存具体日志、源哈希和证据目录。
