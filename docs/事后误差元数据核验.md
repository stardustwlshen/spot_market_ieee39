# 事后误差元数据核验（诊断 schema 2）

本修订只增加执行后诊断的来源、时钟及索引校验，并缓存已经核验过的 forecast ID。不改变过程、预测、优化、执行状态、误差公式、权重、CSV 字段或有效比较行。

## 原生输出

新 writer 把 diagnostic_context 保存到 hydro_window_evidence.json，来源为本次已冻结的 case 配置、provider 来源清单、该日摘要与 DA selected_inputs_hash。上下文有 schema_version=1、origin=native_case_snapshot、configuration_hash、source_manifest_hash、context_hash；registry 同时保留 source_manifest。可与每日 admission 的 DA 输入哈希和 provider_fingerprint 对齐。

诊断 status 的 schema_version=2，同时返回上下文来源/哈希；valid=True 要求：
- evidence、冻结配置和日摘要均明确 dt_h=.25、96 段；整数索引不接受 bool 或浮点数。
- 配置日期、项目时区、来源包时间范围与完整本地 24 小时日一致；源清单指纹、公开资源/时区哈希、actual hash、政策 hash 与 registry 一致。
- DA 是日初 issue；RT t=0..N−1 唯一连续，issue/start 都对应本执行段；ID tau 为0..95整数且唯一递增，与 selected.start 一致，issue 可以依法早于 tau。
- 所有选中轨迹覆盖至同日末，缺段/跨日/错位不接受。合法尚无已执行目标交集的已发布 ID 窗口排除于误差行，并单独记录 excluded_unexecuted_publication_windows，不补实际值。
- Frame 的 DA/ID/RT stage 是去重使用标签。同一预测哈希可以被不同合法容器复用，不强制 frame.request.stage 等于容器阶段；容器若另有显式矛盾 stage 则拒绝。

## 历史归档只读回算

旧档缺新增上下文，不推断或回填。API 支持显式 frozen_context：

`make_diagnostic_context(configuration_base, source_manifest, day_summary, da_selected_inputs_hash, origin='explicit_frozen_archive', source_records=[{'file':原冻结文件名,'sha256':原字节SHA}])`

配置来自原 scenario_snapshot/config/base.yaml；source_manifest/day_summary 来自原 scenario_snapshot/input_source_ref.json；DA hash 来自原 admission.json。调用 `post_execution_forecast_diagnostics(evidence, frozen_context=context)` 或 writer 的同名关键字。已嵌上下文不能被外部矛盾上下文覆盖。

原档缺 project_timezone 时，上述经过核验的原来源包时区可以作为明确依据。配置或来源资料缺失时，status 为 unverifiable，空表加错误原因；不猜时区、步长或日期。派生报告须写独立新目录，origin 明确不是原生记录，保留原输入文件 SHA。

## 性能与等价性

每行比较直接使用已核验的 selected.forecast_id 字符串；原实现逐行调用 frame.forecast_id property 会反复序列化整包。缓存只避免重复哈希，不减少资源/窗口/比较次数，不改变数值及排序。等价验收比较旧新三张 CSV 的字节 SHA；status 因新增 schema/来源信息而预期不同。坏档不会被当作正常运行。
