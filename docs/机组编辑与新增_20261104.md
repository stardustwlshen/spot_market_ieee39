# 机组编辑与新增

## 使用

在“单机报价模拟”的“机组与报价”页签展开“编辑或新增机组”。

- **编辑现有机组**：选择主体，核对节点、容量等参数。原编号与资源类型不可改，需换类型时使用新增。
- **新增机组**：选燃煤、联合循环、燃机、水库式/径流式水电、电池、抽蓄、风电或光伏，填写唯一编号、节点、总装机MW。电池另填MWh，水电/抽蓄另填台数。
- **复制机组**：只复制技术模板，另给唯一编号；不把原机组真实成本复制为新机组成本。
- “核对技术参数”后，初态、效率、爬坡、启停、库容、水文、梯级关系等默认值均可展开修改。水电单机功率由总装机/台数生成。抽蓄初态采用模型实际支持的整厂idle/gen/pump工况，不假装支持独立初始台数。
- “检查参数”只验证。“保存机组”重新验证并提交；“取消编辑”不写入场景输入，重新打开不会回放旧表单改动。

所有新技术、成本、报价默认值都是可查看的合成模拟假设，不是实测电厂数据。默认水文、储能时长等只为便于开始模拟，不构成工程选型或全天可行性证明。固定TIE属于外部计划，不作为新的发电机组类型加入。

## 成本与报价保护

仅所选机组可确认的研究模拟成本/报价依据随新技术参数重新生成。单位电量成本不乘装机容量；只有生成算法规定的启动/在线固定费用按技术容量缩放。原始`fixed_costs.yaml`和`bid_cost_basis.yaml`字节不变，真实或自定义记录不被覆盖。其他机组已生成成本的数值和依据保持不变。原档案后来改成真实来源时，旧模拟覆盖不被重新激活。

新增启用机组同时加入当前草稿，并生成相应模拟报价。已有机组默认保留原报价；容量、SOC或库容改动导致不兼容时，明确报错且不保存。用户可勾选“仅为此机组重新生成模拟报价”，完整旧草稿保留在报价历史备份，其他机组报价不变。停用机组从当前执行草稿移除，但旧草稿备份保留。

保存前检查：全目录编号唯一（含停用机组）、网络节点、类型/预测曲线匹配、有限数值、MW/MWh正值、功率上下限、效率、SOC、上下库联合约束、初态、爬坡、开停时间、整数台数/次数/切换间隔、水电稳定区、水文/季节/梯级拓扑、全草稿市场报价，以及预测覆盖与完整出清输入。检查不调用求解器，也不代表全部时段一定无松弛。

## 保存与并发

先在独立临时副本完成配置、成本、报价、预测与出清输入验证，再对当前场景的技术档案、生成成本和当前草稿作统一提交。表单打开时保存输入指纹，其他页面改变参数、成本或报价后会拒绝过期提交。

提交与现有成本/当前草稿写锁协作；配置读取、运行冻结、场景复制、场景YAML和预测模型写入使用共享场景锁。提交保留旧输入版本，写入中失败会回滚；进程意外中断后停止读取混合输入，运行页提供“恢复未完成的机组保存”，在同一组写锁下恢复旧完整输入。若恢复遇到不属于这次提交的外部改动则停止，而不是覆盖外部内容。此机制针对应用内协作读写和进程中断，不承诺网络文件系统或整机断电的跨文件存储事务语义。

历史运行目录与冻结快照不会被修改。坏旧配置在运行页显示中文业务错误和原始诊断，侧边栏仍可切换场景，不会自动重置原文件。

## 验证

`tests/test_unit_editor.py`与`tests/test_unit_editor_ui.py`覆盖所有九个类型/子类型的新增、已有编辑、真实/自定义成本保护、复制/重复编号、无效输入、检查/保存/取消、表单过期、并发提交、注入写盘失败、意外中断恢复及冻结等待一致性。包含真实Streamlit AppTest与主运行页刷新测试。

另将所有类型逐个经编辑器保存到双节点场景，实际执行8段日前、8个实时窗口及结算，核对主体完整、有限出力及结算对账残差小于1e-6。这是完整小模型流程验证，不是IEEE39全天96段验收。
