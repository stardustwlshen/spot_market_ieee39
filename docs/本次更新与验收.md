# 本次更新与验收（2026-11-03）

## 已合并

- 出力明细支持主体、资源类型、时段组合筛选和一键清除；日前与实时筛选分别保留。
- 分开显示日前/实时弃风、弃光及统计口径；只读电网拓扑支持选择节点、线路和时段。
- 按机组类型、容量和效率显式生成研究成本，保护实测、自定义和历史冻结成本；旧结果可单独补算利润。
- 可预览采用多尺度风光合成模型，不对出清结果作平滑，不冒充真实预测。
- 储能SOC和抽蓄上库容在02、04、…、24点硬等于日前；普通水电原软跟踪不变。增加覆盖日末各锚的资产整数可达后缀，防止提前耗尽抽蓄启动预算。正式网络出清前瞻仍为2小时。
- 当前为单电能量市场，不计容量电价/容量收入；上备用等物理容量约束仍保留。
- 典型场景可组合丰/枯水、风光高/低、总负荷高/低，只建新副本并保存基准，不累乘覆盖旧场景。
- 原区外TIE曲线转换为正的固定需求，按原节点基准负荷占比分配。四阶段逐段总量守恒；不再作为发电或独立供电结算。负荷不报价、不作需求响应，高低负荷场景同时缩放原负荷与转换负荷。

## 旧场景必须显式采用

**替换代码或重启不会自动改写已有场景、历史结果或冻结输入。建议先复制旧场景，再在“运行/单机报价模拟”页选择该副本。**

1. 风光：展开“风光波动与预测误差：预览并采用新版”，选择新版，点“预览风光曲线变更”，勾选确认后点“采用预览曲线模型”。对应 `base.forecast.model: multiscale_v2`。上传列继续优先；已有新能源申报可用功率仍优先，不会被偷偷覆盖。
2. 两小时硬锚：点“本场景改用每2小时SOC/抽蓄库容硬一致”。对应 `MKT.realtime.storage.mode: sced_anchor`、`anchor: two_hour_eq`；前瞻须不少于2小时。历史 `hourly_eq` 是带罚软目标，不能当成严格相等。
3. TIE转负荷：点“将本场景原联络线改为按基准占比分配的固定负荷（下次运行）”。对应 `base.tie_line_mode: fixed_load`、`tie_load_allocation: base_load_share`。缺该字段的旧场景仍为供电模式。
4. 类型成本需要时点击“按机组参数生成模拟成本”，成本与报价分开；随后改报价须另行预览并采用。
5. 典型组合通过独立面板新建副本。若明确同步新能源可用出力申报，界面需另行确认；价格与段量不变。

新仓库模板默认已使用两小时硬锚和TIE转负荷，但风光新模型仍须明确采用；复制旧场景会继承旧选择，而非自动升级。

## 严重缺额，不能把“跑完”当作安全可运行

本次实际执行共有51段切负荷，合计 **3,386.15398 MWh**，峰值 **616.71531 MW**；上备用不足91段、峰值 **845.51217 MW**；线路超限11段、峰值 **29.45588 MW**。这些统计只计每窗实际执行的首段，没有把重叠前瞻窗口重复累计。正式模型已有的罚项使计算能结束，但这个算例不是无缺额、无越限的安全运行计划。

剩余日可达后缀只证明在资产参数、报价约束、目标和连续实际状态不变时，电池/抽蓄有到后续硬锚的可行延续；不保证未来网络、火电、普通水电、备用或供电充足。普通水电软跟踪偏差与电池/抽蓄硬锚严格分开，不应把日志泛称的“锚点松弛”理解为本次硬锚被放松。

日前MIP gap为0.8395%，实时最大为0.9008%，均在配置的1%容差内；`optimal`不是精确全局最优证明。本次没有把所有丰枯/风光/负荷组合穷尽跑完。
