# 报价限制与输入校验

## 作用范围

当前默认启用 `MKT.bid_rules.profile: gd_reference_thermal`：仅参考广东火电申报**曲线结构**，不是把整个模型声明成广东市场复现。广东2025细则第13–19页参考：
https://www.gzpec.cn/law/jygz/202505/P020250516601779253100.pdf

- 火电市场曲线最多10段、价格非递减、数量连续且覆盖最小技术出力至额定出力。
- 最小市场段宽为 `max(5% × (Pmax-Pmin), 1 MW)`；可调范围不足1 MW时取实际范围。
- 本模型已有 `0~Pmin` 内部基座不计入10个市场段，仍保留其出力、价格和成本，不改变优化变量段长。
- **整个内部曲线包含基座都必须非递减，且每段价格都必须在报价边界内。** 因模型分段变量独立有界，允许负市场报价时不能保留更高的零价基座；用户须显式申报基座价格不高于第一市场段。校验器拒绝错误曲线，不会自动改价。
- 火电参考模式默认不额外施加旧研究规则的10元步长、150元相邻价差；可独立配置。`profile: generic`仍可复现旧规则。
- 新能源（wind/pv）默认要求申报曲线完整覆盖0至额定容量；实际出力仍受独立可用预测量限制，不能通过截短报价曲线替代可用量申报。
- 储能/抽蓄充电、抽水曲线仍递减，放电、发电规则沿用研究设定；没有把火电规则错误套到所有资源。

## 报价边界与结算边界分离

`price_limits.bid_min = -50`参考广东2025方案下限（来源：https://www.xinxing.gov.cn/xxxrmzf/xxdt/bmdt/content/post_1961813.html）。`bid_max = 800`仍是本研究假设，**不是广东周度燃煤申报上限，也不是以1800元出清上限代替报价上限**。当前结算 `clear_min/clear_max = 0/800`未改变。

可按资源类型独立设置：

```yaml
bid_rules:
  profile: gd_reference_thermal
  default: {}
  by_type:
    coal:
      price_max: 800  # 示例仍为研究参数，实际应用需填明来源及适用日期
```

可覆写键包括 `price_min`、`price_max`、`segments_min/max`、`strict_monotonic`、`price_step`、`max_adjacent_step`、`min_segment_fraction`、`min_segment_mw`、`min_segment_basis`（capacity/dispatchable）、`require_capacity_coverage`。这些字段不读取 `clear_min/clear_max`。改变研究政策后，既有报价若不合法会被拒绝，不能假定旧报价自动符合新规则。

## 权威输入检查

- `load_bids`读取文件即校验，补齐缺失资源后再次校验。
- `save_bids`先校验，失败不创建新版本、不写文件。
- 直接Python API `build_da_case`也执行相同预检；最终 `scuc.build_model` 每次重新校验可变的case报价，覆盖构建后修改及直接RT/ID窗口，不缓存旧的通过结果；正式建模入口要求所有资源报价完整，缺失即给出含资源名的错误，不在优化边界静默补齐。不能绕过文件/UI入口。
- 拒绝NaN、Infinity、字符串、布尔价格/数量，拒绝未知申报方式、未知启动费状态、负启动/空载费；启动费仍按各机组核定上限检查，不套能量报价上限。
- SOC申报范围必须有序且不能超出设备允许范围；期末SOC必须位于申报范围。
- 新能源可用量须为96点（按配置T）有限、非负且不超过装机的列表；移除了该入口对过大申报量的静默裁剪。
- 文件缺失新增资源时仍保持兼容补默认报价，但输出 `_filled_default` 与“缺省报价补齐”警告，不能隐瞒出处。默认数据仍是研究假设，原有v2报价的价格、数量及补齐的PS1数值没有改变。

当前默认生成器在新默认配置下生成合法报价，且保持原有生成价格/数量；并不承诺任意用户自定义的互相矛盾限制都能自动生成曲线。自定义后需显式调整模板或报价，非法曲线不能靠裁剪通过。
