# 现货利润成本口径修订方案 v1

日期：2026-11-06。状态：只读审计与待批准实施方案，尚未修改产品代码。基线为 `continued_logic_review_20261106/ui_integrated_repo` 的隔离副本。冻结 `final_repo`、历史结果、主分支均不改写。

## 1. 用户口径与不变边界

用户要求：“成本里面不考虑那些运维成本啥的，就考虑发电成本 启停成本这些与现货市场相关的”。本次核算目标为**现货电能现金利润**，不是总投资回报，也不是经过审计的真实电厂利润。采用合成成本时仍标注“研究假设，非实测”。

- 利润 = 日前电能结算 + 实时偏差电能结算 − 合资格发电燃料成本 − 明确定义的在线运行成本 − 实际启停事件成本。
- 电池充电、抽蓄抽水为带符号电能结算，已包含在净现金收支；正价购电支出不能漏扣，负价购电收入不能被取绝对值，也不能在运营成本中再扣一遍。
- 排除固定/可变运维、资本/折旧、寿命损耗/循环折损、融资税费、容量及调频付款、水机会价值、替代补能估价、库存估值、优化松弛和终态罚值。
- 不修改报价曲线、启动/空载报价、报价生成规则、技术参数、优化目标、约束、出力、电价或结算。手工报价仍优先保留。
- 没有明确燃料分解的自定义混合标量，不按比例猜测，不引用当前报价工作表反推；对应新口径利润必须明确不完整。

## 2. 现状完整审计

| 位置/字段 | 实际消费者/当前语义 | 本次处理 |
|---|---|---|
| `profit.py` 的 thermal `scalar_marginal_cost_yuan_per_mwh` | 乘实际发电 MW×dt；原研究值为燃料+VOM；`bid_simulation.py` 同时以它作报价锚 | 原字段不改。只在独立新口径中使用有证据的燃料分项 |
| wind/pv 同名 scalar | 研究模板为风光VOM | 在新核算中排除，不删报价依据；自定义记录不得只凭资源类型假设其全部是VOM |
| hydro 同名 scalar | 原模板6元/MWh及生成器均明确 `variable_om`；水机会价另在报价工作表 | 新核算排除6元VOM与机会价；不把水价值当燃料 |
| storage `discharge_degradation_yuan_per_mwh` | 电池放电寿命/循环折损25/35/45元/MWh；不是购电 | 新口径排除；真实充电结算仍保留一次 |
| pumped `generation_vom_yuan_per_mwh` | 抽蓄发电可变运维10元/MWh | 新口径排除；发/抽启动及抽水结算仍保留 |
| thermal `fixed_online_cost_yuan_per_h` | 在线状态×dt；历史来源仅称从技术假设复制；不能据字段名证明不含固定运维 | 只有显式声明“空载燃料”或“不含运维的在线运行费”才能计入。历史含义不明时标缺项，不静默改称燃料 |
| thermal `fixed_startup_cost_yuan_per_start` | 实际离线→在线次数，不乘dt | 保留独立启动成本，不读当时报价；跨日使用真实执行起点 |
| pumped `gen_start_yuan_per_unit_start` / `pump_start_yuan_per_unit_start` | 实际发电/抽水在线台数的正增量，元/台次 | 保留独立启动成本，不重复累计前瞻窗口 |
| 停机费 | 全仓成本核算没有独立停机费字段或扣费公式 | 不伪称已有。新档案支持显式元/次或元/台次停机费，研究默认明确为0；只能实际在线台数减少计费，不乘dt，不更改调度目标 |
| `research_defaults.py` / `research_cost_setup.py` | 生成旧现金成本与报价工作表的版本化覆盖层；原文件和手工记录受保护 | 旧两类产物保持语义/数值；独立生成新口径成本及依据，不重写原scalar |
| `profit_recalculation.py` | 只读校验旧执行证据，另外封存成本补算；目前假设单一旧公式 | 新旧核算策略明确分开，先核对旧记录，再生成新口径报告 |
| `unit_input_view` / `market_views` / `profit_recovery` | 目前把VOM/退化直接显示为独立核算成本；完整旧利润无补算入口 | 新口径显示真正计入项与来源；旧结果标旧口径。完整旧结果也允许显式按新口径另算 |

旧代码费用公式为：`rate×P×dt + online_rate×u×dt + start_rate×starts + pump_start_rate×pumpstarts`。其购电不重复扣减的结构正确，不能因本次缩小成本范围而破坏。

### 来源链与已识别限制

1. `fixed_costs.yaml` 为独立参数档，`generated_research_costs.json` 仅在原记录/原来源指纹仍匹配时覆盖；自定义记录优先。`load_fixed_cost_profile` 不能为了新利润改变给报价模块返回的数值。
2. 新生成的热电成本有冻结 `evidence.parameters.fuel_price/heat_rate/variable_om`，可验证 `scalar = fuel_price×heat_rate + variable_om` 和记录哈希后分解；不从当下可编辑的报价工作表读取。
3. 原仓库精确已知研究档可使用版本化显式分解表（同时核对类型、完整记录、来源，而非仅凭ID）：C1 270+10、C2 285+12、C3 300+15、CCGT 390+15、GT 600+20 元/MWh。这是已知研究假设的分解，不是实测证明。来源或记录变化即不自动套用。
4. 在线费历史说明并未严格排除运维。旧档案缺少明确定义时新口径不自动全保留或全删除。可以由“采用现货研究成本”明确保存**新的**非运维在线运行费假设，或手工填写；不得把后来假设伪装成旧冻结证据。
5. 新研究默认值可沿用已批准类型/容量模板的燃料热耗和启停金额；在线额必须在新档案中明确声明是“不含运维的在线运行费研究假设”，不是宣称恢复历史真实分项。已有自定义混合成本不覆盖。

## 3. 数据与版本方案

新增独立 `config/spot_market_costs.yaml`，版本 `spot-market-costs-v1`；利润策略为 `spot_energy_cash_v2`，历史策略为 `legacy_cash_operating_v1`。新文件只供核算，不被报价/SCUC/SCED读取。

逐机组记录包含类型、来源、假设/观测状态、适用字段和明确定义。最小字段清单：

| 资源 | 可编辑且实际计入的字段 | 单位与边界 |
|---|---|---|
| 煤电、CCGT、GT | 燃料发电成本 `fuel_cost_yuan_per_mwh`；在线费 `online_cost_yuan_per_h`；在线定义 `online_cost_basis`；启动费 `startup_cost_yuan_per_start`；停机费 `shutdown_cost_yuan_per_stop` | 有限非负；燃料值不含运维且须说明增量口径；在线定义只能空载燃料或不含运维的在线运行费；元/事件不乘dt |
| 抽蓄 | 发电启动/停机费；抽水启动/停机费 | 元/台次；对实际ng/np的正/负变化计费；切换分别记录退出与进入 |
| 风光、水电、电池 | 明确新口径“不计运维/退化，当前无燃料及独立启停费用”的记录与来源 | 这是明确范围下的不计项，不是把缺失真实费用补零；当前不新增水电/电池启停调度模型 |

允许显式0，禁止NaN/inf/布尔值充数/负费用/未知类型或字段。停机费研究默认0必须记录为本版本假设，不宣称历史曾有已核实0费用。不将未知在线定义按0略过后宣称完整利润。

优先级：手工现货成本记录 > 已明确接受并封存的新现货研究默认 > 可验证旧记录的合资格分项。没有合资格分项则该成本/利润不完整，净现金结算仍独立可看。所有被排除项、缺失项和来源在折叠明细可查。

“现货研究成本”与原来的“报价成本依据”是不同产物。生成或编辑新档只更改这个核算文件，绝不自动采用报价预览。历史原始档案、原生成层、手工报价均字节保留。

## 4. 编辑、保存、生效与冻结

1. 运行页选中机组时提供紧凑“现货核算成本”表单。短help解释单位/范围，主面不恢复长说明。显示最终采用值、来源、缺项原因，旧VOM只在“排除项/旧档案”折叠中列示。
2. 检查不保存，取消不保存，浏览不物化继承字段；无改动保存保留原文件字节。浮点采用足够显示精度，不round底层值。
3. 保存采用成本锁+场景输入锁、源指纹并发检查、原子替换和不可变版本备份。原始固定成本、原生成成本、单位与现货成本任一相关来源变动需重新核对。运行中禁用表单，后端也检查，不允许改冻结快照。
4. 保存后重载新文件，下一次冻结/新利润分析采用同一解析器，显示策略版本与成本来源hash；只改核算不触发报价或调度。
5. 复制场景显式携带新档。单日 freeze 已复制整个config，应验新文件存在和来源指纹；多日 `_cost_files/_freeze` 目前仅列 fixed/generated，须加入新成本文件，冻结逐日独立数据。不得跨日读取可变主场景成本。
6. 只重算历史利润时，需明确选择本次新成本版本/策略并预览。沿用历史执行量、结算和真实起点，单独发布不可变报告；不会重跑市场或覆盖原 `operating_profit_*`、summary、snapshot。

## 5. 历史兼容与校验

- 没有策略字段的历史输出按 `legacy_cash_operating_v1` 解读，不能换标签假装新口径。所有新的summary、逐时/逐机组/类型表及manifest记录核算策略、参数来源、冻结hash和不计项。
- 历史重算先按原档案/原策略复核旧成本，随后按新策略和明确采用的新参数重算。两个公式不能混用，否则剔除运维会被误报为“原记录不一致”。
- 原补算版本1继续只读验证。新版本计划/manifest带策略版本与新成本来源hash；读报告时以其策略复核，不使用当前默认策略。新旧报告都不能被默认值变更重算或静默覆盖。
- 当前已确认 TIE兼容缺陷：C的 `rt_units.csv` 有17个利润主体和冻结定义的TIE，旧 `_grid` 只允许前17个，导致合法旧结果无法预检。修复仅允许冻结配置中启用的tie，逐个验证其完整96段网格、类型和有限数值，再分离利润主体；未知extra、缺时段、重复仍拒绝。
- 与跨日工作者的 `archived_actual_initial` 合并：t0热电在线和抽蓄ng/np优先实际首态；连续档有admission/checkpoint却缺首态应拒绝；旧单日兼容配置初态时明确说明。新停机次数也用同一实际起点，日界不虚增启动/停机。
- 若历史不足以支持严格重算，停止并说明缺证据，不能绕开验证。冻结C来源存在已解析 `fixed_cost_profile.json`，原snapshot没有fixed_costs.yaml；只能验证JSON本身与输出一致，不能声称验证缺失原YAML字节。

## 6. C 算例只读复核结果

证据：`docs/现货成本口径_C只读复核_20261106.json`。从冻结C逐时读取并检查96/96段、17个利润主体共1632行、RT的18主体网格（含合法TIE）；对每主体逐段校验实际功率/电量、实际起点启停、成本档参数、独立现金结算和旧成本公式。CSV四位小数造成的最大逐段成本重构误差0.0035元，在随费用倍率变化的舍入界内；核查前后11个源文件hash完全一致。

PS1逐项：
- 售电两结算收入269065.8049元，抽水带符号结算−323955.0000元。
- 净现金−54889.1951元。发电实际启动3台次，抽水启动4台次；2000×3+4000×4=22000元。
- 旧逐时运维合计8946.4287元。新口径去除此运维、不改启动/结算，利润为**−76889.1951元，约−7.6889万元**。
- 旧逐主体汇总原值净现金−54889.1952、运维8946.4286、利润−85835.6238元。逐时导出后再求和与未舍入原汇总存在末位差，本次不伪称完全相同精度。
- 初上库200、末196.09375万m³；库存差不折现金，不是严格等库存盈利比较。
- 此复核并不把全场旧在线费认定为燃料，也没有宣称新口径全场利润已验证完整。

## 7. 计划实现边界与验收

预计新模块：现货成本解析/来源/保存、现货成本UI。小hunk涉及 `profit.py`、`profit_recalculation.py`、`research_defaults/research_cost_setup`（仅独立核算产物）、`scenario.py`、运行页及单位信息表、利润仪表/历史重算UI；多日成本冻结与总计由对应工作者协调。不覆盖其跨日起点hunk。模型文件与报价生成不得改变。

必须验证：
1. 每类型的燃料、在线、启停事件×正确单位；不同dt同轨迹一致；停机0/非0、部分抽蓄台数、日界初态、非执行前瞻不计入。
2. 运维/退化/机会/替代电能/罚值均不计利润，正/负价充放/抽发现金恰扣一次；缺定义不补0。
3. 自定义混合scalar保持原值和报价，未知分解使新利润不完整；改报价工作表或手工报价不改核算燃料。合法已知版本分解检查来源和完整hash。
4. UI编辑→检查→保存→重载→成本消费/新报告，no-op/取消/运行中/并发/无效值/重复点击安全，版本可查。
5. 新旧报告策略隔离；旧报表读取不改文件；C在独立证据副本发布新报告、复核−76889.1951；原C完整hash保持不变。
6. 冻结已知TIE完整网格允许，未知/重复/缺项拒绝；历史证据、成本档或报告被篡改均拒绝。
7. 单日/多日成本包均携带新档，运行后源成本变化不影响冻结报告；跨日合计不重复付费，不混合策略版本。
8. 固定输入/报价下真实短DA+RT前后比较，dispatch/LMP/settlement不变而利润按新成本改变；结合现有成本生成/报价/场景复制/历史补算/UI聚焦回归。区分聚焦通过与全套未运行。

本方案经项目Page记录并回读确认后才实施；如审计发现须扩大模型或更改报价的事项，另提案，不夹带在本次核算修订里。
