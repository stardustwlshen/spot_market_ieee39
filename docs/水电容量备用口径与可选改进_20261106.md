# 水电容量备用口径与可选改进

历史审查说明：以下记录的是修订前的容量备用口径。用户随后明确要求修复水量不足仍计上备用的问题，本轮已选择并先行记录15分钟、时段末库存的增量水量筛查方案。新候选的实施和验收另见《水电上备用增量水量修订方案》及本轮最终验收，不再以本文件中的“建议先保留当前规则”作为最终决定。

## 结论

当前水电备用沿用已选定的**容量口径**：在线稳定运行区上限减去计划出力。代码按这条规则计算是自洽的，但“上备用缺额为0”不能解释为该备用一定能在缺水时持续交付。这是模型适用边界，不把增加水量约束当作本轮既定修复。

## 可复现的边界算例

使用当前真实建模入口和HiGHS，构造1台水电、15分钟时段：

- 稳定运行区：45至100 MW；初态在线、初始出力45 MW。
- 初始库容14.05万m³，最低及期末要求库容10万m³，外部来水0。
- 耗水率1 m³/s每MW，上备用需求50 MW，仅水电提供备用。
- 最优计划出力45 MW，期末库容10万m³，模型上备用55 MW，备用缺额0，备用影子价0。

计划耗水为45×0.25×0.36=4.05万m³，已用尽可调水量。如在同一时段额外激活50 MW并持续15分钟，另需50×0.25×0.36=4.5万m³，总耗水后的库容仅5.5万m³，低于物理下限。即使把备用理解为下一时段开始激活，在来水仍为0的情况下也无可用水。这不表示默认全天结果已发生该事件，只说明现有验收不能排除这种边界。

复现：`inspect_reserve_boundary.py`；完整数值：`hydro_reserve_capacity_counterexample.json`。其中55 MW是求解器选择的无报价冗余容量，需求50 MW已满足；不应把多出的5 MW解释为实际采购或市场付款。

## 可选改进，需要先明确研究目标

1. **维持容量备用研究。** 保持当前模型与既有结果可比，结果标明“容量备用”，另报水位、出库、爬坡及线路可交付风险。适合研究容量余量与出清机制，不宣称事故持续保障。
2. **增加保守的增量水量筛查。** 在选定持续时间H下，按与电池/抽蓄一致的时段末库存约定，约束 `0.36×water_rate×H×水电上备用 ≤ V[t]−vmin`。这可排除上述反例，但不代表完整激活轨迹；不能直接把未来来水算两次，也不能忽略可削减弃水可能替代额外耗库。需约定来水、基准发电、弃水及日末/日电量限制的处理，评估保守程度。
3. **建立备用激活场景。** 显式比较基准与激活后的功率、出库、库存轨迹，同时检查响应爬坡、稳定区、生态流量、出库上限、梯级时滞及网络送达，火电和储能采用一致的响应/持续时间。此法更接近可交付备用，但会改变可行域、备用稀缺程度、调度和电价，也增加计算量。

建议先保留当前规则，并增加上述压力诊断和容量口径提示；如果研究目标要论证“可交付备用/安全充裕性”，再选择第2或第3条并单列新旧口径对照，而不是悄悄修改现有价格结果。
