# 报价备份与旧档案恢复补充复核（2026-11-04）

在 90d3771 基线的既有完整用户操作验收后，继续检查电厂报价人员的恢复边界。本轮不重复全天市场求解，不修改备用规则、求解精度、物理约束或不利组合的备用缺额。

## 新发现与修复

1. **下载后没有常规恢复入口。** 原工作台可以下载完整当前报价，并发冲突也要求用户先下载再刷新，但上传入口只有存在旧编辑历史时才出现。普通场景或重新打开的会话没有办法在网页使用自己的备份。
   - 现在正常打开的工作台均有折叠的“从文件恢复报价（仅所选机组）”。
   - 上传只作预览，明确点击才替换当前所选机组。文件中的其他机组、当前成本、技术参数和原报价版本不被替换。
   - 恢复前完整报价另存历史备份；恢复操作遵守既有并发校验，不能覆盖另一页面的新报价。
   - 保留已上传文件不会在后续刷新时自动重新应用，不会吃掉恢复后的手工改价。
2. **旧申报方式字段可能使页面崩溃。** 旧档案或恢复文件将 mode 写成列表或对象时，原界面查中文说明会抛出 TypeError，报价校验还没有机会提示。
   - 上传的结构错误现在先给出中文提示，当前报价不变。
   - 对已经存在的坏档案，页面保留原值并禁止运行，允许用户明确点击“切换该机组为报量报价”修复；不静默改档。

## 检查内容

- 八类资源分别恢复备份：煤电、联合循环、燃机、风电、光伏、水电、电池和抽蓄。核对预览不改值、只改所选主体、恢复前完整备份、磁盘保存、手工继续修改及全新会话接续。
- 坏 JSON、缺少所选主体、错误的主体/曲线/启动费/申报方式结构不会变成可采用报价，也不会改写当前报价。
- 已恢复的违规数值保持可见，运行按钮禁用，明确修复后才可运行。
- 两会话并发时，后一个恢复操作保留本页编辑但不能覆盖先保存的报价；运行继续禁用，下载备份仍可用。
- 空载报价、单次启动报价、期末 SOC、日末上库库容各连续修改四次。每次与磁盘一致，新会话继续最后值；冻结提交与模型 load_bids 读取完全一致，其他机组与原存档保持不变。
- 收入/成本/利润展示保留原有独立口径：现金结算不冒充利润，充电/抽水不重复扣款，缺成本不当零，不改变已有负利润。
