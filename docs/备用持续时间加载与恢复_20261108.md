# 备用持续时间加载与恢复（2026-11-08）

## 已核对的事实

- 远端 `main` 是 `5c6ab3c`。本 PR 不改 `config/modes.yaml`、备用校验或日内默认 `enabled: false`。
- 仓库模板 `config/modes.yaml` 的 `MKT.reserve.T_dur_h` 是浮点 `0.25`。注释和 README 都把它标成研究假设：备用能量按 15 分钟折算，不是省级规则原文。
- 自已发布的 `6e83ba2` 起，模板里就有这项 `0.25`。首次打开网页时，`ensure_default()` 只在还没有 `scenarios/默认/config/base.yaml` 时，从仓库模板复制一份新场景。已有场景不会被整文件覆盖，也不会在读取时自动升级。
- `load_config` 在储能备用开启，或常规备用提供者含在运水电时，要求 `reserve.T_dur_h` 为有限正数。缺键、显式空值、`0`、负数、布尔、字符串、`NaN` 和无穷大原来都会得到同一句 `reserve.T_dur_h 必须为有限正数`。仅凭这句不能判断现场原值。
- 高级参数保存会拒绝 `0` 和非有限数，并且不改原文件。它不能把模板里的 `0.25` 写成非法值。正数校验继续保留。

## 不能从现有代码单独断定的部分

别人 pull 之后如果仍使用自己已有的 `scenarios/`（`.gitignore`，更新说明要求保留），读到的是旧目录，不是这次 pull 的模板。现场只有那一句旧报错，没有原值、类型和路径。因此不能断定那一份文件是缺键、`0` 还是字符串。本仓库当前模板和由它新建的默认场景可以加载。

## 这次允许的兼容

不在加载时改写任何已有值。只有键完全不存在、并且没有未完成的机组保存事务时，页面提供一次显式操作：先把 `modes.yaml` 原样备份到 `config/backups/`，再只写入 `T_dur_h: 0.25`。`0.25` 小时沿用模板里已有的 15 分钟研究假设，不新造参数。显式空值、`0`、字符串和非有限数保持不动。存在 `.unit_edit_pending.json` 时不补写，仍走「恢复未完成的机组保存」，不删除事务标记。
