# 水电软终态前瞻补充

状态：第一版实时软目标发现可避免的弃水与末态短缺；本补充先同步docs与Page再实施。用户允许实时末库容/SOC偏差的要求保持有效，不能改回硬末态或人为增加弃水价格。

## 1. 实算与反事实

第一版1000元/可放电MWh软目标，丰水、日内关闭，完整运行96段、实际备用缺额0，但H1末库容17839.878704812453，低于18000目标160.121295187547万m³，对应370651.1463元模型末态成本。电池/抽蓄日末目标满足。这个成本不是市场结算付款。

22:00起水库17656.998704812453，未来8段按已锁日前台数最低发电340/300/260/260/220/220/220/220MW，最小出库408/360/312/312/264/264/264/264m³/s，来水均560。最多再回蓄182.88万m³，恰得到实际日末值；到此时再提高罚价已无济于事。

然而这不是全天经济必要损失：独立反事实仅将首段弃水减少1779.125502m³/s，其余96段发电、启停和网流不变，全程库存提高160.121295万m³后仍满足原物理界和历史窗口带，日末达到18000，可降低末态成本370651元。全天RT水电发电反低于DA；额外弃水357.6505万m³，减发省水197.5292万m³，净差等于末态短缺。不能解释成“多发电耗水”或“已经选择了全日最优权衡”。

根因是H1日前水价值96点均0、弃水无额外目标成本，当前软终态成本仅在2小时窗口覆盖24:00时进入；原整数后缀只包含电池/抽蓄。取消水电严格回归包络后，早期窗口没有看到将来的软短缺成本。

## 2. 最小前瞻修订

1. 只对RT价值法、终态政策soft、当前窗口尚未覆盖日末的水电添加独立的未来终态短缺项，不改日前、日内或历史hard政策。新默认显式配置 `value_method.hydro_lookahead: reference_continuation`；缺少该键的历史场景保留off，可显式设off进行前版对照，不自动改写已有场景。
2. 窗口末τ之后，按本轮选定DA/ID参考的Qout延续估计后续出库，不能只按最小出库假定以后随时可以少发水电。已知来水仍按现有无来水预测误差假设；梯级上游到水遵守既有滞时，已执行的到水来源读实际历史，尚未执行部分取同一选定参考Qout，不使用未来实际值。未来参考出库与台数/价值属于同一已验证交接包。
3. 参考续程净回蓄量为 `R_ref=Σ(qin+q_up_ref−Qout_ref)×dt×0.36`，形成独立软式 `V_τ + z ≥ v_end−R_ref, z≥0`。它估计沿该参考续程的预计日末短缺，而非最大物理回蓄证明；不把右端截断进物理边界，不重新塞进硬状态带。min-Q乐观回蓄可作单独诊断，但不能作为唯一前瞻成本：本例它直到17:45才开始计罚，仍看不到首窗可避免弃水。
4. 目标增加 `ρ×z/(0.36×water_rate)`，ρ沿用当前软目标1000元/可放电MWh研究假设。z是存量，不再乘dt；只罚不足，不奖励或惩罚超额留水。它不是新增弃水报价，也不是固定正水价值。日末延续价值仍0，原有有符号SCED价值不截断。
5. 当日末进入原2小时窗口时不再添加该前瞻项，由原单侧日末软目标接管，不能重复计罚。前瞻期间仍只执行首段，参考回退跟随现有成包来源；实际水库与历史出库不重置。
6. 该项是**基于选定参考续程的预计末态短缺成本**，不是未来网络、水电爬坡、梯级联合可达性或全天经济最优的证明。尚未执行的上游出库仍是参考预测常数，不与当前窗口新决定的出库完全联立，不能冒称梯级最大物理回蓄证书。原电池/抽蓄整数后缀保持有限成本软目标不变。
7. 新Block/松弛与目标成本单独导出：时段、主体、参考来源/轮次、参考续程净回蓄量、窗口末最低参考库存、实际窗口末库存、预计未来短缺、等价能量和优化成本。它与当前窗口状态带、已执行日末偏差及紧急回退分开，不能把前瞻窗口成本跨轮加总为实际成本或结算。
8. 默认辅助定价保留该项；显式remove只在独立定价克隆中去掉该项及其成本，不改变正式调度。重建目标不得把已移除成本带回。仅当前硬参考带确证不可行时的受控软化，不删除有限成本前瞻项。

## 3. 验证要求

- 微模型验证前瞻软约束始终可用偏差满足，而物理库容/生态/整数约束未松弛；不把正负价值取绝对值；统一能量转换、无重复dt，日末无重复罚。
- 覆盖参考来源/回退、未来参考出库、梯级滞时、已执行上游历史与尚未执行的参考量、超物理范围的软目标、辅助保留/移除及目标重建。
- 首先重跑丰水ID关，独立重验上述可避免末态成本反事实；不因新增一条软式或仅单测通过就宣称问题已消除。
- 此前严格目标及第一版软目标四场景均仅为历史基线。修订通过后在同一最终代码完成丰/枯×ID开/关四组、100/300罚价灵敏度及完整测试/页面验收，实际偏差、备用、ID失败及模型成本如实列示。
