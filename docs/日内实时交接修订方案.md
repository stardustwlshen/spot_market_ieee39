# 日内实时交接修订方案

## 范围与依据

最终修改回到原项目仓库 `stardustwlshen/spot_market_ieee39`，用户提供的 ZIP 是他人改动版本，用作待审查、整合的差异输入。快照分支 `fix/value-based-rt` 的提交为 `4b71e2a`，历史上从 `main 6e83ba2` 连续增加 7 个提交；该分支存在于快照，尚未据此认定远端已有同名分支。本轮在独立 Git 工作分支核对历史并整合，保留原仓库内容及未提交工作，不覆盖用户原文件夹，不擅自合并主分支。用户审阅并明确确认修改完成前，不推送远端。

用户要求重大改动先在方案文档和 Page 写明依据，再修改代码。以下重大模型方案在两处写入并核对后才进入相应实现；有关终态价值经济含义的改变须先明确口径。独立的非模型批跑安全修复先行处理，范围与验证见《多场景批跑安全说明》。

沿用的研究决策：确定性出清；15 分钟粒度、实时前瞻 2 小时、只执行首时段；储能及水库完整状态动态；PS1 与电池采用相同市场规则；状态价值来自日前或日内固定整数后的调度 SCED，而不是辅助算价模型；窗口目标使用 `−v·X`，正值鼓励留能，不把负值取绝对值或截零；备用能量采用时段末库存；报价和结算下限 −50；线路罚 1 万、备用罚 10 万；不设下备用。保留可选锚点和硬约束失败后的软化流程。

`handoff_source: intraday` 是交接来源默认值，不等于 `intraday.enabled: true`。现有运行是否开启日内市场继续由显式配置决定，不能因更新代码而暗改用户保存的场景。

## 当前实现和已确认缺口

- 日内窗口覆盖当天剩余时段；已有轨迹、价值和水电台数交接，以及资源开关。
- 实时的所有固定火电启停均从最近计划 `plan` 读取。若日内和实时分类配置不同，原本应锁日前的煤机可能错误承继日内计划。
- 日内参考只提供整体来源标签，逐资源关闭交接后仍可能显示来自日内；轨迹和价值缺失时也不能准确说明各自的实际来源。
- 部分缺失数组会静默沿用旧轮，短数组或非有限值可能报错或进入模型；没有统一的逐主体、逐字段有效性和回退记录。
- 价值法从选中参考的日末数组取储能/抽蓄终态目标。日末目标应独立固定为日前已确认目标，而不能随日内参考改变。
- `state_values()` 最后一个点取终态约束对偶。水电是 `V_T ≥ v_end`，其下限影子成本不能直接解释为跨日残值；日末继续加 `−v·V_T` 不是常数。储能/抽蓄日末硬等式下该项是常数，但软化后也不再恒定。
- 验收脚本对部分 CSV 名称漏写 `.csv`，缺失数据被当作通过，且未完整核对状态偏差带松弛。现有旧的“全部通过”说明不是本快照的完整验收结论。
- 硬到软回退捕获所有异常，包括辅助算价故障，且每次重启窗口求解预算。软件错误不能触发约束放松，软化重试也不能重复取得一份完整时间预算。
- 主流程 `full.checks()` 的“无松弛”也漏掉状态偏差带。已用一时段电池目标 180、最高可达 120 的模型复现：状态带松弛 60，但旧判断仍给出 `rules_satisfied_no_slack=True`。摘要和结果页面必须使用完整松弛判据。
- 水电审计仍把实时稳定区台数一律与日前比较，开启日内继承时会把正常交接误判。应与该窗口实际选取并记录的参考来源比较，同时继续单独验证物理台数、出力区间和爬坡约束。

## 拟修正的交接规则

1. 明确火电分类及来源。日前锁定类始终从日前计划读取；日内可调整类在开启日内交接且已有有效日内结果时继承最新日内启停；实时自由模式保留显式配置。沿用原关闭交接语义：`handoff_source: day_ahead`、`handoff.commitment: false` 或 `intraday_commit_rt: free` 时，快速 GT 仍在实时自由优化，不把它称为“继承日前 GT”。已开启继承而该机组日内启停缺失时才锁回日前并记原因。重叠、未知或无覆盖的分类不能依靠字典顺序悄悄决定，应在进入求解前给出可理解的配置错误。
2. 每个资源分别解析参考。记录实际采用的轨迹来源、价值来源、日内轮次与回退原因，不用一个整体标签代替全部主体。无日内轮时采用日前；缺失、长度错误、越界或非有限的日内字段不得直接进入模型。日前基准也无效时停止该次求解并说明字段，不能用零冒充有效价值。
3. 轨迹和边界保持一致。电池、抽蓄分别使用所选参考的轨迹和 SCED 价值；水电同时核对稳定区台数、出库流量和库存，以免新的参考与旧的物理量混用。审计比较对象采用每窗口已选定的真实参考，不能把正常日内变更硬判为违反日前计划。参考选取不改变实际执行状态的逐时递推。
4. 日末目标与参考分离。电池/抽蓄仍回到日前日末目标；水电仍执行已声明的日末最低库容；日内参考仅影响中间窗口参考，不重写日末约束目标。
5. 终态价值单独处理。中间时段保留 `v_t = −dual(c_X[t+1])`。覆盖日末的窗口不再把终态目标影子成本当作跨日残值，保留日末约束并令额外延续价值为零；若今后研究跨日价值，应另行显式建模。微型单库 LP 已复现原因：日前最低终态 2、上限 10、热电价 100 时，终态下限对偶及其有限差分均为 100；实时热电价 50 时，不加残值留水 2、热电成本 100，而误加 `−100V` 留水 10、热电成本 500。此为定位问题的微型反例，不是 IEEE39 全天结果。终态目标影子成本仍可单列输出，不把它改符号、取绝对值或截零冒充正确的中间时段价值。
6. 保留历史兼容。读取和展示旧场景的实际规则；新配置可供显式采用，不能把旧场景的 `hourly_eq`、`fixed_da` 或价格下限 0 静默替换。当前运行报告必须携带冻结的配置来源，不能用今天的仓库配置冒充历史运行规则。
7. 验收采用缺失即未验证。价格、终态、松弛和结算等必需证据缺失、空表、字段错误或包含非有限值时不能输出通过。备用缺额按研究设定单列，不能与线路、状态带等松弛混为一谈。主流程摘要、`rules_satisfied_no_slack`、结果页面和离线验证脚本均须纳入 `state_band_slack_max`，并分清 MW、MWh 和万立方米，不直接把不同单位求和解释为物理量。
8. 限定软化触发和预算。只有得到明确的硬约束不可行结果才重试软带；数据校验、程序错误、辅助算价失败、取消和超时不冒充不可行。硬求解、软重试及算价共享窗口总预算，输出每步结果和耗时，保留原始异常链。

## 验证计划

- 保留已有价值符号有限差分及正负极端值方向测试，记录测试数、跳过原因和求解器版本，不把夹具测试当作全天验收。
- 加入煤机日前锁定、GT 日内继承及实时自由、来源开关、单资源关闭、分类冲突、缺失/NaN/短数组、连续多轮交接及跨日末目标回归。
- 对终态水电做可重复的微型 LP 和固定整数有限差分，区分终态目标扰动与免费库存注入。
- 为验收脚本注入超限价、非零状态带松弛、缺文件、空表、缺主体及不完整时段，确认均不能误报通过。
- 注入软件异常、辅助算价故障、取消和预算耗尽，确认不发生错误软化；明确硬不可行时仍执行一次受剩余预算约束的软化重试。
- 按最终实现跑相关回归和全套测试，再做至少一组包含日内与完整实时 96 段的集成运行；仅完成定向测试时明确列出未跑项目。
- 同步 README、实时价值法说明和页面来源标签；不改写历史验收事实，不把旧版本通过数用于新快照。
