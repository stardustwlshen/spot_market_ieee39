# 实时电池SOC与抽蓄上库容每两小时硬一致

本次按用户研究要求采用北京时间02:00、04:00、…、24:00对齐日前同一时刻库存，不作为现行省级规则的合规结论。

## 物理与时标

- E为电池电量MWh，SOC=E/ecap；Vu为抽蓄上库容万m³。相同容量下硬约束E相等即SOC相等。
- 全日从北京时间00:00起，索引k存储第k段结束状态。15分钟下k=7/15/95对应02/04/24点。窗口[t,t1)包含t1边界上的状态，但不把窗口起点前一段重复算为待优化变量。
- 00点用实际初态。窗口若从已到达偶数小时开始，先验证当前实际库存等于上一段日前状态，偏差时报错，不能悄悄重置。
- 使用实际dt_h计算两小时步数，拒绝dt_h与interval_min不一致、两小时/前瞻无法整除步长、前瞻小于2h、binding_periods非1。不能用四舍五入改变时标。
- 日末窗口按剩余时段截短，不额外加奇数小时窗口末锚点。24点目标用当天最后一段DA状态，不用DA[0]，也不把次日初态另算一个控制段。当前单运行日模型不支持自动跨日，必须换用新日前计划并传递连续实际状态。
- 测试用缩短物理时域可在非锚点结束，此时没有额外期末一致承诺。常规短时试跑只截短执行段数，日前/前瞻仍按原全日数据。

## 硬约束与旧版兼容

`two_hour_eq`构造独立c_anc_eq等式，E/Vu锚点的上下偏差变量固定为0、偏差罚系数为0；不存在“付罚即满足硬一致”的含义。物理电量/库容范围、效率、充放互斥、抽发台数/转换间隔/启动预算仍保留。目标缺失、非有限或超物理范围直接报错，不裁剪目标。求解无可行解时报告窗口、策略、实际库存和目标，并停止；不会自动改用软目标。

旧hourly_eq和window_end_pct维持带罚软目标语义；缺少anchor键仍走旧默认，历史配置不会静默迁移。新仓库默认/新建场景采用two_hour_eq；已有场景须通过报价模拟页显式按钮或修改自身modes.yaml迁移。修改不影响历史运行的冻结输入和结果。

普通水电的tracking_policy、同钟点日前窗口末库容软追踪及归一化罚系数保持不变。辅助算价remove策略仅在独立克隆移除E/Vu硬跟踪等式和历史软跟踪约束；正式SCED模型、执行出力、库存不受影响，克隆量不得执行。

## 能证明什么

储能灵活性扩大是相对于“每小时同样硬一致”：同样物理边界下取消01/03等奇数小时等式，使两小时内充放能量更自由。旧代码hourly_eq实际为软约束，原本可付罚偏离；因此新硬策略与旧软策略的可行域不构成一般包含关系，也不能保证所有算例成本降低。

专项测试分别验证时间轴、短窗口、24点、缺失/越界目标、步长校验、真实不可达求解失败、辅助克隆隔离、16段滚动的02/04执行状态一致、普通水电软目标不变，并在相同硬度下对比每小时与每两小时模型。

汇总检查新增窗口目标数量、已执行锚点数量、电池MWh误差和抽蓄万m³误差。它检查正式窗口及已执行首段端点，不把前瞻值当已执行值，不把短时运行冒称完整日验证；零松弛不替代状态误差/目标完整性校验。

两小时前瞻保证优化窗内看到下一固定时钟锚点，但不构成整天递归可行性证明。抽蓄转换间隔、已用启动预算、未来预测变化仍可能使后续硬目标不可达；遇到这类失败保留已执行前缀并报告，不能把本次小算例通过推广为所有96段场景均可行。

## 余日资产可达性保护（滚动启动预算修复）

仅检查2小时窗内硬库存仍可能出现陷阱：抽蓄为近期经济性消耗抽水启动台次并停机，随后虽有足够装机功率，剩余启动预算却不足以在24点恢复库存。2026-11-03转换后负荷场景的原运行在t88被HiGHS明确判为infeasible：PS1已用抽水启动3/4台次，22点空闲、上库104.76190476190482万m³；末2小时到200需1200MWh抽水，但仅能再启1台、最多600MWh。不能以更大罚系数或放松末态掩盖。

新two_hour_eq每轮在正式窗口的最终电量、库容以及抽发模式/台数后连接一个**到运行日末的资产整数可行后缀**：

- 继续遵守每个剩余偶数小时硬目标，不只检查下一个目标或一个能量上界。
- 电池使用充放互斥、充放效率、物理与申报容量、申报SOC界和自调度功率（如有）；后缀要求storage_binary=true，LP松弛对照须使用历史策略，不能混用后冒称物理证书。
- 抽蓄使用有效上下库界、定速/变速抽水功率、发电最小出力、台数、全厂互斥、跨窗口转换间隔，以及从实际已用预算扣除后的“当前窗+整个后缀”合并启动上限。保持在线可延续台数，不会把每个新窗误算为全部重新启动。
- 后缀只提供存在性证明，目标权重为零；不执行、不结算，不读取未来实际负荷/新能源，不延长原2小时市场网络窗口，不改其他电源、负荷、备用需求或普通水电软目标。
- SCUC一起决定整数，正式SCED固定当前窗与后缀的所有整数并保留证明约束，仍只执行首段。下一轮实际状态和累计启动量来自首段，不来自后缀计划。
- 辅助算价preserve保留该证明；remove只在克隆中去除整个后缀证明，正式调度不变。阶段记录单独标示后缀整数和资产证明，不把它们混入已执行机组出力。

**条件性范围：**在资产参数、申报约束与剩余日前硬目标不变时，上一轮的可行余日资产轨迹为下一轮提供资产级延续见证；启动累计以实际正台数增量传递。这不是未来网络、火电、水电、备用或预测扰动的全系统递归可行证书。成功到24点和库存硬一致仍可能伴随切负荷、线路或备用松弛，必须分别披露。

验证包括：错误早启动序列无保护可行、加保护严格不可行；双机完整后缀可行且合计启动不超限；跨边界转换间隔；电池效率/申报价容量；全部未来锚点覆盖；辅助克隆隔离。对原失败输入复用保存日前计划，修复后从00点重放96段，48个实际库存锚点误差均0、日末电池[100,200,100]MWh、PS1上库200万m³、抽水启动总量4台次。该运行仍存在正式模型的切负荷/线路/备用松弛，不作为全系统物理可行结论。
