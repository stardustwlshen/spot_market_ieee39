# 多场景批跑安全说明

批跑入口为 `bash scripts/k_batch.sh [并发数]`，也可直接用开发环境 Python 运行 `scripts/k_batch.py`。Shell 入口默认使用项目 `.venv/bin/python`，可用 `K_PYTHON` 指定现有解释器；不会自动安装软件。

## 输入与范围

- 默认负价场景需要已有的 `outputs/k_bids/bids_v901_negprice.json`，或显式传 `--negative-bids 文件路径`。文件缺失或不是完整报价 JSON 时，在启动任何求解前停止。
- 不跑负价场景时使用 `--skip-negative`，批次记录明确标为未验证，不伪造负价输入。
- 使用 `--dry-run` 检查任务和输入，不创建结果文件、不启动求解。
- 每项任务都启用 `main_full.py --read-only-inputs`：曲线仅在内存生成，不改写 `data/profiles`，不自动保存缺省报价。默认命令行入口的原行为不变。
- 不执行任何 Git 恢复、检出、重置或清理，不删除已有文件。

## 结果与退出状态

每次运行创建独立的 `outputs/k_batches/batch_*` 日志目录和唯一结果后缀；不根据旧 `summary.json` 跳过任务，不覆盖旧批次。可用 `--log-root` 选择批次日志父目录。

每个 CLI 运行在求解前独占创建新输出目录，冻结生效配置（含命令行覆盖）、网络表、实际报价与曲线；目录已存在时要求更换 `--tag`，不会覆盖旧运行。输入快照仅证明输入已保存，不代表求解完成。

`batch_manifest.json` 保存解释器、完整命令、开始前及完成后的源码与输入哈希（包含外部负价报价文件）、跳过项、每个进程的退出码和日志位置。这些哈希不是冻结输入快照，批跑期间不要修改代码或输入；发现文件变化会返回非零状态。任一进程失败，批跑入口同样返回非零状态。取消时只终止本批次明确启动的子进程，保留已写日志和结果。

进程成功不代表模型验收通过。价格、状态动态、日末、松弛、结算和交接来源仍需单独检查。仓库原 `PACKAGE_MANIFEST.json` 描述较早的发布包，不作为本次批次的完整性证明；本批次以实际文件哈希为准。

示例：`K_PYTHON=/已有环境/bin/python bash scripts/k_batch.sh 2 --skip-negative --dry-run`。
