# 类型容量成本与默认报价v5实现

日期：2026-11-06。对应先行方案：`docs/默认成本与报价分类型分容量审计_20261106.md`，项目Page序列17已先行同步。本文记录隔离副本实现及聚焦验收，最终整合版全天DA+RT96另行验收。**所有下列价格、燃料和热耗参数、容量指数均是研究假设，不是实测电厂成本，也不是省级报价规则。**

## 采用范围

- 仓库新增 `default_bid_model: cost_basis_v2`，从独立的逐机组成本档案与机会/策略参数生成默认报价。缺键旧场景保持 `legacy_v1`，非法开关报错。历史固定模板单独保留为 `legacy_default_bids`，仅用于旧场景、历史回归与报价形状初始化。
- 追加报价v5，不重写v1—v4、不改旧场景或当前手工草稿。新默认不再继承v2的CCGT演示加价与ES2优惠演示价。已有成本档案优先，未因新容量代理而重写它们。
- 原始 `config/fixed_costs.yaml` 完全未改：C1/C2/C3核算成本仍280/297/315，CCGT405，GT620元/MWh。现存档案中的逐机组差异保留，新生成器不是既有档案的静默替代品。
- 新增资源或用户明确生成/采用研究成本时，使用 `typed-capacity-research-defaults-v2`。煤、CCGT、GT按类型参考点和容量进行有界热耗/运维修正。旧生成器v1档案可读取，保持原成本数值、哈希和原生成版本来源，不静默重算。
- 初次v5按丰水期生成。切换丰枯水只改物理水情，不自动修改任何已存报价或当前手工草稿；若要随水期调整水机会价，需明确生成预览并采用。丰枯受控对比继续使用同一冻结v5报价。

## 新机组的类型与容量逻辑

所有火电记录视为独立启停的机组/热力块，不能把若干完全相同机组聚合后的总容量当成更高效单机。沿用参考点：煤646MW、30元/GJ、9GJ/MWh、VOM10；CCGT687MW、60、6.5、15；GT300MW、60、10、20。

- 增量热耗：h_ref×clip((P/P_ref)^(-0.08),0.90,1.15)。
- 可变运维：VOM_ref×clip((P/P_ref)^(-0.05),0.90,1.15)。
- 单位边际成本：燃料价×增量热耗+可变运维。
- 在线费与热态启动费：各类型原参考值×P/P_ref。新增机组技术模板和独立成本生成使用同一函数，消除此前所有类型统一10元/(MW·h)、400元/MW启动的模板冲突。
- 类型参考点、0.08/0.05指数、0.90/1.15边界及启动温态比例都是显式研究假设。生成依据保留实际容量、倍率和是否到界。不能用该代理否定用户提供的高效小机组/低效大机组成本。

## 避免重复计费

- 明确生成热耗是增量高位热耗，已移除“3.6/该热耗就是平均效率”的展示字段；历史未明确的热耗标为未声明平均口径。
- 0—Pmin能量已经按能量价计费，不再加进空载截距。能量价阶梯是报价策略，不是实际分段热耗积分。
- 能量费用按MW×dt，在线费用按在线状态×dt；启动费用按启动事件或新增台数，不乘dt。
- 电池/抽蓄补能价和水机会价只用于报价。实际充/抽电费用已在净结算收入计入，核算层不重复减一遍补能费或损耗费。
- 修改报价只影响出清报价，不改现金核算成本；明确成本预览只改所选资源，不覆盖受保护手工报价及其他机组。

随机平移当前报价时，原成本生成依据移入历史记录，避免把先前成本公式误标为新随机价格的直接来源。成本+随机预览仍保存本次新依据。

## 验收证据与边界

证据目录：`docs/evidence/cost_bid_defaults_20261106/`。

- 新测试 `test_capacity_cost_defaults.py` 覆盖类型/容量分离、旧v1读取和版本来源、历史开关、显式成本优先、缺档案不回退、丰枯冻结、手工保护。
- 完整默认17资源、96段输入构模，并从实际Pyomo目标表达式提取线性系数，核对全部火电能量/在线/启动，全部电池充放及抽蓄发抽/启停，水电与风光能量项。此项是构模/目标系数验证，不是全天求解成功证明。
- 机组编辑既有全类型8段DA+RT实算在本分支回归，包含煤、CCGT、GT、风、光、水库水电、径流式水电、电池、抽蓄。它是8段前缀，不称为全天市场验收。
- 最终合并水电修改后，集成分支统一运行DA+RT96、受控丰枯对比、展示与结算核验，不复用修改前结果冒充新版本。
