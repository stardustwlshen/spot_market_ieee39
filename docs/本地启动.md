# 本地一键启动

## 只需做一次

1. 安装官方 CPython **3.12 或 3.13**。Windows 安装时勾选 **Add Python to PATH**。Python 3.11 不兼容当前锁定的 scipy/networkx。
2. 下载或 clone 完整项目。不要只复制 `app/`，也不要把其他人的虚拟环境一起复制过来。
3. Windows 双击 `start.bat`；macOS 双击 `start.command`；Linux 在项目目录运行 `bash start.sh`。

第一次安装需要网络和磁盘空间。程序仅安装在项目自己的 `.local-app/venvs/` 内，不改系统 Python 或既有 `.venv`。
为避免全局 pip 配置把依赖装到错误目录，启动器忽略 pip.ini/pip.conf；需要单位镜像或代理时，可显式设置 `PIP_INDEX_URL`、`PIP_PROXY`、`PIP_CERT` 等网络环境变量。它不会自动改用第三方镜像或关闭证书校验。
它会检查所有运行依赖的版本、二进制导入，并用一个极小模型核对 Pyomo 与 HiGHS；这不是一次市场求解。
成功后自动打开 `http://127.0.0.1:8501`。浏览器没自动打开时，复制窗口中的地址即可。

保留启动窗口。用完后按 Ctrl+C 关闭网页服务。**如有后台求解，请先在网页请求取消并等待结束；关闭网页不会强杀求解器。**
一键入口只监听本机，没有新增联网共享或登录功能。

## 不使用 Git：ZIP 下载与更新

第一次取得完整源码ZIP后，先解压到自己的普通文件夹，再运行文件夹里的启动入口。不要在压缩包预览窗口中直接双击，也不要只解压app目录。

更新ZIP时先在旧网页确认所有求解已结束，正常关闭旧启动窗口，保留整个旧文件夹作备份。将新版解压到一个新文件夹。需要继续使用旧场景和历史时，在新版首次启动之前、且两个副本都没有后台任务的情况下，把自己旧的scenarios、runs、outputs复制到新版对应目录，保留旧副本；目标目录若已存在同名场景或运行，先核对，不直接覆盖。随后用新版入口启动检查；不要覆盖新版src、app、config、bids，也不要搬运.venv或.local-app虚拟环境。如果你曾直接改过根config、bids或data，请先单独备份并与新版逐项比较，不要用整目录覆盖来处理差异。

只在确认原后台服务已经停止后搬移运行记录，不要同时启动新旧副本。存在未知或取消中的记录时先看[运行中断安全恢复](运行中断安全恢复.md)，复制旧活动记录不会解除其占用。新旧默认的差别在网页中明确预览；旧场景不会自动升级。

## 每次更新后

先在网页确认没有正在求解的任务，关闭旧启动窗口，再用自己原来的 Git 工具更新代码，重新使用相同入口。
启动器**不自动 pull，不 reset，不清理工作区，也不自动处理合并冲突**。Git 提示本地修改时，先备份并核对，不要用删除目录来解决。

- 运行依赖未变化时，检查已有环境后启动，不每次联网安装。
- Python 或依赖清单变化时，创建另一份独立环境，保留旧环境；可能需要额外磁盘空间。
- `scenarios/`、`runs/`、`outputs/`、既有报价和用户上传文件保持不变。
- 更新源码不等于迁移旧场景。旧预测模型、成本、抽蓄锚点等，仍由用户按页面提示预览并明确采用。
- 运行期间若修改代码/默认配置，窗口会提示等求解结束后重新启动，不会自动中断计算。

不要在市场求解期间更新代码：后台进程仍可能延迟读取模块，文件监测只负责提示，不能把一次正在运行的求解变成完全隔离的旧版本快照。

## 常见问题

| 提示 | 处理 |
|---|---|
| 找不到 Python / 版本不支持 | 安装 CPython 3.12/3.13 后重新打开终端；Windows 检查 PATH。不要用3.11重试当前依赖。 |
| 无法创建虚拟环境 | 确认 Python 包含 venv/ensurepip；Debian/Ubuntu 通常需安装对应版本 `python3-venv`。修复后重新启动。 |
| 依赖安装失败 | 看窗口给出的日志，检查联网、代理、磁盘空间和对应平台wheel；修复后重新启动会继续准备未完成环境。脚本不自动更换镜像、降低版本或忽略校验。 |
| 已安装环境检查失败 | 保留日志，不要删除场景。可请维护者核对，或关闭全部相关程序后，将日志里对应的 `.local-app/venvs/py…` 环境目录改名备份，再启动重建；不要把整个项目删除。 |
| 本副本已在运行或准备 | 找到原来的启动窗口。系统锁会在程序退出后自动释放，不需要删PID文件，也不要强杀不认识的进程。 |
| 8501端口占用 | 关闭你确认的原网页服务，或改用 `--port 8502`。脚本不会结束占用端口的其他程序。 |
| macOS不能双击.command | 在终端进入项目，运行 `bash start.sh`；不要为此关闭系统安全保护。 |
| 网页仍提示旧场景问题 | 环境正常不等于输入正确。保留原场景与日志，按页面明确修复或复制新场景；启动器不偷偷替换用户配置。 |

诊断日志在 `.local-app/logs/launch-时间-编号.log`，包含安装/启动错误和项目路径。请先检查日志中是否有不宜分享的个人路径或网络配置，再发给维护者。

## 可选命令

Windows 以下将 `bash start.sh` 换成 `start.bat`；macOS/Linux 都可在项目目录运行：

```sh
bash start.sh --install-only       # 只准备环境
bash start.sh --check              # 检查已安装环境，不安装依赖或启动网页
bash start.sh --port 8502          # 改本机端口
bash start.sh --no-browser         # 不自动打开浏览器
```

开发者可直接运行 `python scripts/launch_app.py`，使用当前支持的 Python；这与包装脚本相同。
原 `scripts/run_app.sh` 仍是手工 `.venv` 的后台工具，不能管理新入口的进程。普通用户请只使用上面一种入口。

## 验证范围

本次在 Linux 实机执行首次环境准备、依赖/HiGHS检查、网页健康检查和失败分支测试。
Windows/macOS 包装和锁/路径分支做静态或模拟检查，**尚未在对应操作系统实机验收**。
通过安装检查不代表所有历史场景或完整市场模型都通过验收；正式使用仍应跑一份已知算例核对结果。
