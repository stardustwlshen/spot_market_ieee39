# 枯水、低新能源、高负荷：备用不足的完整诊断

## 范围与结论

基准是新光伏总装机2152MW、multiscale_v2、固定来电供给、负荷不报价、电池/抽蓄每2小时硬锚条件下的枯水×风光0.8×负荷1.1合成研究日。冻结原归档为`../ieee39-final-evidence/pv2152_dry_lowre_highload_full96`；独立诊断树为`../ieee39-dry-reserve-diagnosis`，起点c1f829a。case/scuc/rolling/full/da/pipeline求解代码相对原50223f4无变更。未改整合工作树、未推送、未改任何默认参数。

原归档96段RT全部执行，切负荷、线路越限、过剩功率、弃风光均为0，电池/抽蓄硬锚误差为0；但40个执行段有上备用不足，最大237.228332MW，积分1105.803976MW·h。日前600秒预算到限，有可行解，gap1.9793715%，未达到原1%要求；RT全部达到1%。网络和能量平衡可行，不等于备用合格或SCUC达到目标差距。

## 不是简单的总装机不足

- CCGT687MW在原DA和RT全天未开机，RT按既定规则锁定煤电/CCGT启停。
- GT在40个不足时段已经在线，通常75MW出力加225MW上备用，不能笼统建议“启用燃机”解决。
- 水电RT模式为window_end_da，不仅跟踪库容，水电每个稳定运行区的在线台数也固定为DA。508MW铭牌容量不能视作每段可用容量。08:30固定区间上限只有187MW，出力130MW、上备用57MW。
- 枯水水电声明日电量5000MWh与同日末库容/来水约束并列，后者更紧：220m³/s来水、1.2m³/s/MW耗水率、期末不低于期初，DA水量上限4400MWh。RT水电目标为软跟踪，因此这个上限是DA硬末库容的推导，不可未经说明扩展为所有RT轨迹的硬上限；本次实际RT恰好4399.999999999842MWh。
- 实际相对DA净负荷误差，在08:30为+218.8917MW、17:45为+207.9178MW、21:45为+289.1660MW。原DA备用没有不足，但这些误差消耗在线出力空间。
- 电池并非普遍耗空：08:00三组段初库存100/256.387/100MWh，合计400MW上备用已全用；此时不足142.326MW仍存在。ES2在23:15、23:30另受15分钟增量备用库存约束。

## 当前运行工况的容量上界

在本次缺额段均无弃电、切负荷、过剩功率的前提下，可逐段写出当前工况上备用上界：

在线火电容量 + 已锁水电区间上限 + 电池400MW + 已在线抽蓄发电容量 − 实际净负荷 − 抽蓄抽水功率。

储能充电可中止的上备用口径使电池基准功率在上述式中抵消；库存约束可能进一步降低该上界。此是给定在线/工况的上界，不证明另一整数计划或另一DA计划也无解。

38/40个缺额段，实给备用恰等于该上界，全部可用功率余量饱和；给定工况的下界累计解释1078.660621MW·h，即总缺额约97.55%。剩余两段是23:15、23:30的ES2库存约束。逐段数值见`baseline_shortage_details.csv`，每个资源见`baseline_shortage_resources.csv`。

21:45最差点：
- 在线火电2536MW，其中C1/C2均到646/725MW，C3仅余23.1255MW，GT提供225MW备用。
- H1出力340MW、备用168MW，固定区间上限508MW。
- 三组电池备用100+197.8120+100MW。
- PS1段初上库194.047619万m³，22:00硬目标200万m³，最后15分钟必须抽水300MW，不能同时发电留备用。
- 上界2536+508+400−2330.062478−300=813.937522MW，低于需求1051.165854MW，故缺237.228332MW。

## 场景归类与求解改进边界

冻结预检明确给出`unverified_candidate`、`designed_stress_event: none`。该组合通过了乐观总量必要条件，却未通过完整运行备用验收。分类保持“未验证常规候选，本次完整运行备用验收失败”；不能追溯声称它本来就是专门设计且允许失败的压力事件，更不能继续标作完整通过的常规日。主审查的普通枯水1.0/1.0控制组已完成全96并经独立归档复核：DA gap0.1050243%、RT最高0.8706047%，DA/RT零切负荷、线路越限、备用缺额，硬锚一致；弃风520.6356MWh、弃光412.191725MWh。归档`../ieee39-final-evidence/final_c1f829a_dry_nominal_full96`。它支持区分普通干季与本次不利叠加边界，不能替代本次失败组合的结论。

日前未达到1%是最优性证明不足，不等于所有物理约束不满足；原DA松弛为0。本次后来完成了一项严格不改模型的有效单场景改进，但不伪称是通用提速修复。

- 可保持数学模型不变的候选：原生搜索/启发式参数、严格计入同一600秒的可行热启动、已有约束可推导的变量界与冗余有效不等式。具体可从初末SOC和最大充放功率推导逐时SOC可达区间，再据此收紧逐时功率big-M；该界必须由原能量等式与硬边界推导，不能夹带“基准出力+备用全激活”新约束。当前已有静态储能big-M及同型水电台数聚合，不能把已实施措施冒称新改进。任何新界需证明不切掉原可行整数解，跨场景对照目标/下界/时间并保留失败记录；本轮未实测此候选的加速效果。
- 现有`solver.tighten=true`不是可直接启用的等价收紧。scuc.py的启停段出力+备用上限从Pmax减至Pmin，实质改变启停备用能力；`commit_step_periods=4`改变启停可选时刻；取消储能互斥、软化硬锚、改罚项/备用规则、加容量均改变问题，不能用作无声明的提速。
- 已复用近期`../ieee39-cloud/solver_strategy_revision/deliverables/日前求解策略三组复核.md`：旧冻结场景600秒/4线程，强制parallel=on的末gap4.0937%优于默认4.4829%，shifting为5.4161%，当时三组均未达0.2%。该证据不能保证当前1.979%能降至1%，也不支持旧文档中“多线程一直无效”的绝对说法。
- 本次预留比较仍需同时看incumbent与best_bound。报价目标差异若小于各自未证明最优的区间，不应声称已证明成本排序最优。
