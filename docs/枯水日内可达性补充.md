# 枯水日内可达性补充

状态：真实失败已复现并定位；以下修订先写入 docs 与既有方案 Page，核验两处一致后才实施。尚未获得修订后的四组通过结论。

## 1. 实测与定位证据

同版本代码、报价 v1、枯水期、日内开启、默认分级及价值法下，已执行到 20:00，tau=80 的日内剩余全天 SCUC 被 HiGHS 判为不可行（kInfeasible，primal_solution_available=False）。不是超时或辅助算价失败，没有产生完整日结算。独立重放得到相同失败，并保存真实 16 段剩余窗口。

PS1 此时上库为 200.11390371625168 万m³，日前日末目标为 200 万m³，机组全停。已用抽水启动数 4，恰好达到全站日上限 4；尚余发电启动数 6。只需净减 0.11390371625168 万m³，但单台最低发电一段为 150 MW × 0.25 h / 9.6 = 3.90625 万m³。停机不满足目标；启动会过冲，而抽水启动已无剩余，无法回补。

独立分组可行性试验结果：

- 完整失败模型：infeasible。
- 仅去掉 PS1 终态目标：optimal；仅去掉抽水启动上限：optimal。
- 分别去掉水电终态、电池终态、火电锁定、发电启动上限或转换间隔：仍 infeasible。
- 松弛全部整数域：optimal，但使用约 0.01458 台发电机，是不允许的分数机组。
- 仅 PS1 的独立微模型：最小可达末库容 60，最大 200.11390371625168，目标 200 位于该连续区间内，却仍精确不可达。因此仅用最小/最大库存包络不能代替整数可达域。

证据文件保存在仓库 docs/evidence/value_day_end_20261105/，试验只修改诊断克隆，未放宽生产模型。以上是原失效状态定位，不是修订后验收。

另一个枯水期、日内关闭的对照已完整运行 96 段，但 23:45 时段上备用缺额 13.6248 MW，累计 3.4062 MWh。主流程正确标记并非所有需求无松弛。离线证据验收通过不表示备用需求全部满足。

## 2. 修订方案

1. 在 `value` 模式且实时窗口尚未覆盖日末时，复用现有储能/抽蓄剩余日资产可达性后缀，新增明确的 `day_end` 目标策略。只连接日前已确认的日末 SOC/上库目标，不新增整点或偶数小时锚点；历史 `two_hour_eq` 策略继续按其原目标集合运行。
2. 后缀从当前 2 小时窗口的末状态连续接到 24:00，保留电池充放互斥与功率/容量约束，抽蓄整数台数、抽发工况、定速泵功率、最低发电功率、转换间隔及状态动态。当前窗口启动数加后缀启动数，共用扣除实际已用启动后的同一份日预算。不得增加启动配额、取整日末目标、放松整数或重置实际状态。
3. 后缀仅证明存在一条资产级可行续程，目标权重为零。后缀数量不执行、不结算、不累计为实际量，仍只执行原 2 小时市场窗口首段；原窗口末价值、偏差带、日末目标及正式/辅助算价来源不因此改写。固定整数 SCED 必须同时固定该后缀整数，防止价格 LP 改用分数续程。
4. 明确这是**微观资产可达性，不保证全网联合可行**。后缀不添加未来网络、火电、水电、备用或预测误差场景，不宣称多日优化或跨日残值。只有资产约束，不是把实时出清窗口扩到全天。
5. `value` 的当前窗口硬带明确不可行时，仍按既有同预算两阶段流程尝试当前带软化，但不撤掉剩余日硬终态可达性证明来绕过资产死角；若连软带加资产证明也不可行，则明确停止并保留证据。日末已进入当前窗口时无后缀，继续原显式日末约束及受控软化记录。旧 `two_hour_eq` 的显式软化语义不被暗改。默认辅助克隆保留证明，旧显式 remove 策略仅影响独立辅助模型，不改变正式执行来源。
6. 导出目标策略、后缀范围、日末目标、共享启动预算及证明误差，明确数量不执行与保证边界。若运行失败或存在备用缺额，继续如实披露，不用缺证据或不足的连续库存包络判为通过。
7. 该补强增加后缀变量与整数约束，不改报价、物理参数、启停分类或日末申报。记录实际求解耗时和 gap，保留原预算，不通过放宽精度或提高时限掩盖性能变化。

## 3. 验证要求

- 真实 PS1 终态死角的可重复微模型：旧连续包络可接受而整数末态不可达；新后缀必须拒绝该状态，或在前序窗口选择可达的状态和启动安排。
- 日末目标集合仅含 24:00；跨窗转换间隔、实际启动累计及共享预算；电池/抽蓄动态；后缀非执行性、零成本及固定整数 SCED；默认辅助保留；value 软带重试不撤后缀。
- 历史两小时锚点及旧场景不自动迁移，重跑已有相关回归。
- 修订完成后，重新在同一最终代码上运行丰水/枯水 × 日内开/关四组完整 96 段、全套测试及结果页检查；不得把此前通过数或失效前缀当作最终成功。
- 结果报告分开列出程序完成、物理/状态约束、备用缺额、软化、日末、经济指标与耗时。即使证据核对通过，也不把有备用缺额的场景称为全需求满足。
