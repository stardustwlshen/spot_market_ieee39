# 水电 ut/dt 真实约束方案

状态：仅设计，待 Page 审阅确认；未实施模型约束、未修改生产树、未提交或推送。


## 1. 供 Page 先行的结论

1. 目前水电 `ut/dt` 可以保存，但没有进入水电约束。不能把增加说明、保存字段或结果列称为实现。
2. 现有 `delta[电站,稳定区,时段]` 是聚合台数，不能恢复具体哪台开停、已连续开停多久。把总在线台数套用火电最小开停公式，或按台数增减猜测启动/停机记录，都不可靠。
3. 推荐最小可靠实现：保留现有站级出力、稳定区、水量、报价和结算结构，增加有稳定编号的逐台在线/启动/停机变量及实际持续时间状态，通过台数等式连接聚合稳定区。它保证逐台最小开停时间，不声称新增逐台出力、爬坡或水头模型。
4. 必须同步覆盖 DA、ID、RT、正式 energy_sced、辅助算价克隆，以及现有水电日电量下限续程模型。只有同一个正式 SCED 的首段可以推进实际状态。
5. 旧数据没有逐台历史，不能默认填“已满足 ut/dt”。启用前必须明确初始化来源。可接受显式逐台记录，或用户选择的保守下界初始化；未知不是 0 小时实测值，更不是已经满足要求。
6. 当前架构是单日模型，没有已验证的跨日承诺消费链。本方案首版建议采用明确的“日内完成”边界：新启停的最小持续时间必须在日末前完成；跨滚动窗口用不执行的启停续程保护。该边界有保守偏差，必须随方案确认，不能悄悄添加。若要求允许晚间启动并跨日继续，必须先扩展跨日初态导入与验证，不能只输出一个剩余时长文件就宣称支持。
7. 上述修改可以实施，但不是几个表单字段的小改动。正式启用前，需要独立分支/副本、迁移确认、微型反例测试、全回归和完整 DA+ID/RT 验证。现有测试通过不代表本方案已经通过。

## 2. 用户目标和本次边界

用户原话：

- “1、输入的参数都可以手动修改吧，也能够手动添加机组等吧？2、界面中没必要的解释或描述就不要写了；”
- “然后那些藏起来的高级参数要解释分别是什么，然后要允许修改并且生效”

## 4. 为什么“只看总台数”不够

例如 2 台同型机组，时刻 0 的总在线数为 1。机组 A 可能已经在线 3h，也可能刚启动 0.1h；另一台 B 可能已停机 3h，也可能刚停机 0.1h。两种状态具有相同在线数和站级功率，但当 ut=dt=1h 时，下一时刻允许的启停完全不同。

连续两段总台数都是 1，也可能是 A 一直开着，或 A 停、B 启。`max(n[t]-n[t-1],0)` 为 0，不能识别后者。禁止全站同段有启有停又会错误排除两台均已满足最短时间时的合法换机。

“把最近几段新增台数累加”可以发展成严格的同质群组/年龄队列模型，但必须有完整初始队列、双向转移、同段交换与队列状态推进的证明。它不是现有台数模型加两个式子。本首版不选择该路线，避免用较难审计的队列代替清楚的逐台状态。

## 5. 最小可靠模型：逐台承诺，站级功率保持

### 5.1 数据与身份

每个启用新版的电站有 N 个稳定、唯一的机组编号。编号不能因排序、重新求解或窗口推进而改变。每个编号对应同一台已声明机组；研究模拟编号须明确是用户声明的模拟初态，不能伪装成设备实测。

保留现有电站级 ut/dt（小时），作用于站内每台同型机组。首版不开放每台不同最短时间、稳定区或容量；未来扩展时必须真正建模，不能先存无效覆盖字段。

建议输入结构（概念契约，最终键名可随高级设置方案统一）：

```yaml
hydro:
  - id: H1
    n_units: 4
    ut: 1.0
    dt: 1.0
    commitment:
      schema_version: 1
      mode: unit_duration_v1
      terminal_policy: complete_within_day
      initial_state_at: "2026-07-15T00:00:00"  # 与运行日、时区一致
      initial_units:
        - {unit_id: H1_U01, online: true, elapsed_h: 0.5, elapsed_kind: exact, source: user_declared}
        - {unit_id: H1_U02, online: true, elapsed_h: 2.0, elapsed_kind: exact, source: user_declared}
        - {unit_id: H1_U03, online: false, elapsed_h: 1.0, elapsed_kind: exact, source: user_declared}
        - {unit_id: H1_U04, online: false, elapsed_h: 3.0, elapsed_kind: exact, source: user_declared}
```

这里的数值只是接口示例，不是对当前 H1 历史的判断，不得自动写入默认场景。

日初 `sum(online)` 必须等于现有 `init_units_on`。UI 应从逐台表派生初始在线台数；兼容导入仍同时提供两者时不一致必须报错，不能偷偷纠正。日初出力仍遵循现有 `init_units_on × init_p_unit` 的相同初始单机功率假设。滚动后仍存真实站级 P，不反推每台 P。

每条状态至少含：unit_id、online、elapsed_h、elapsed_kind、effective_at、source、state_version。elapsed_kind 可为 exact 或明确的 lower_bound；未知没有数值。运行冻结文件记录模型版本、单位编号、参数 hash、时间网格和初态来源。

### 5.2 变量、连结和启停逻辑

设 h 为电站，i 为站内机组，k 为时段，步长 Δh。新增：

- u[h,i,k]∈{0,1}：本段在线；不是用 P>0 事后判断。
- s[h,i,k]∈{0,1}：本段边界由停到开。
- d[h,i,k]∈{0,1}：本段边界由开到停。

必需约束：

```
u[k] - u[k-1] = s[k] - d[k]
s[k] + d[k] <= 1
sum_i u[h,i,k] = sum_z delta[h,z,k]
```

k=0 的 u[k−1] 必须是该窗口开始前的已执行实际状态（日初为明确输入），不是所选 DA/ID 参考的前一段。

保留现有：`Ph = sum_z pz`，`Lz*delta <= pz <= Uz*delta`，`sum_z delta <= N`，水量、爬坡、出力、生态流量、日电量和备用等约束。既有 delta 继续为整数，哪怕计数等式在某些场景会产生冗余，也不在本次顺带改掉。

一个电站不同机组可以同段分别启动和停机；禁止的是同一台机组同时 s=d=1。该限制即使 ut=dt=0 也保留，避免虚假启停。

同质前提下的连接充分性：每段在线集合大小为 n，delta 将 n 分配到各稳定区；可任取同样大小的在线ID子集分配到这些区。某区有 δ 台且 pz∈[δL,δU]，总能拆成 δ 个落于[L,U]的功率。现有模型没有逐台功率跨时约束，所以逐台承诺与这些逐段分配并不冲突。该论证不适用于异型机组或逐台爬坡，故不允许未经建模的逐台参数覆盖。

### 5.3 最小时间与非整倍数时间网格

按真实边界时刻定义。一次启动发生于时段 k 的开始，u[k] 持续覆盖该整段；下一次停机时刻减本次启动时刻必须不少于 ut。停机同理。

均匀网格的等价标准式：

```
Ku = ceil(ut / Δh)
Kd = ceil(dt / Δh)
sum(s[j], j=max(0,k-Ku+1)..k) <= u[k]
sum(d[j], j=max(0,k-Kd+1)..k) <= 1-u[k]
```

ut/dt=0 时对应求和为空，仍保留转移逻辑。实现建议统一构造基于精确时刻差的事件窗口，再与此式交叉测试。配置数值按其十进制表示解析为统一的时长/边界类型，禁止用 round；不要用较大的 epsilon 把真实的 1.00001h 当成 1h。数值容差只处理求解整数容差，不能随模型长度累计缩短要求。若使用 Decimal(str(value)) 或 Fraction(str(value))，计算边界与审计使用同一精度规则，配置快照保存原值。

例：Δh=0.25、ut=0.6，00:00 启动后最早 00:45 可停，不是 00:30；初始已开 0.2h 时还需 0.4h，只能在 00:30 边界允许停。初始持续时间不必是 Δh 整倍数。

### 5.4 初始剩余承诺

窗口开始前在线且已持续 a：若 ut−a>0，则所有开始时刻距窗口起点小于 ut−a 的段固定在线；停机情况同理。约束必须作为显式等式存在，不能只调用变量 `.fix`，以免后续参考固定覆盖物理要求。

若采用 lower_bound 持续时间 a，则真实持续时间至少 a，按 ut−a/dt−a 计算是保守限制。状态不变时下界增加 Δh；发生新启停后，当前新状态的持续时间从已执行首段 Δh 起为 exact。不得把 lower_bound 改标实测 exact。

### 5.5 稳定区与初态：保留已修好的边界

- 日初所有初始在线机组仍按输入 init_p_unit，必须在允许稳定区；0 台在线要求总出力 0。
- 滚动初态必须将逐台 online 加总，与 `hydro_online` 一致；再用实际 `hydro_p` 检查精确的在线机组稳定区 Minkowski 和，不得只检查 0≤P≤nPmax。
- 2 台单机区间 [10,20]∪[80,100] 时，100MW=10+90 合法，不能用平均 50MW 位于禁区而拒绝；总功率 60MW 不合法。
- 当前站内同质、没有逐台出力动态。只加承诺与计数连接即可保证每段存在一个与在线机组集合一致的稳定区分配，无需伪造已观测的每台功率或稳定区。
- 新版不输出声称真实的逐台功率/稳定区轨迹；如果将来需要特定水轮机逐台爬坡、跨振动区动态、不同容量或检修状态，必须引入对应逐台功率/区间变量和物理约束。这些不属于本次最小实现。
- 若稳定区允许 0MW，则在线可以是已同步但零功率状态。这是所声明稳定区的模型含义，不应偷偷改成“发电量大于0才算在线”。

## 6. 窗口末、日末与承诺续程

### 6.1 推荐首版边界

推荐 `terminal_policy=complete_within_day`，并明确展示为“最小开停时间须在日末前完成”。单日末点不是可以清零物理承诺的机会。

对每个候选启动边界 Bk：若日末 E−Bk < ut，令 s[k]=0；停机按 dt 同理。若已带入的初始剩余承诺大于窗口起点至日末的剩余时间，当前模式不具备完成能力，直接报明确边界错误，而不是丢弃债务。

这会阻止例如 23:30 启动一台 ut=1h 的水电，也会阻止 23:30 停机一台 dt=1h 的水电。它是保守研究边界，会影响晚间组合与价格；不是“真实系统必须在午夜完成启停”的物理规律。需要 Page 审阅认可后才能实施为新默认。

调试只运行前 p 段时，规划日末仍是原完整生产日末，不得把 pΔh 当新的关账终点。导出 p 段真实状态的未完成承诺，状态为“前缀/未完成”，不能声称已完成全天最短时间验证。

### 6.2 跨 RT 窗口不能截断

新增共享的 `hydro_commitment` 块，承诺时间索引覆盖本次窗口开始至运行日末（DA、ID 原本到日末；短 RT 延伸只有承诺变量）。主窗口 u 与主模型 delta 连接。正式功率、水量与结算仍只在原窗口中，承诺后缀不执行、不结算、无单独能量报价成本。

这使本窗口末启动的 ut 不会因窗口截断而消失，也让初始承诺、窗口内新启停、后缀及日末边界由同一套逻辑处理，避免两段各自“重置初态”。

RT 的后缀政策需要明确，首版不扩大现有参考的硬锁定范围：

- value/fixed_da/window_end_da：主市场窗口仍锁定所选参考稳定区台数。窗口之外若已经有日电量下限资产续程，则保留该续程现有的参考台数锁定，并连接同一逐台承诺块。
- 窗口之外没有既有水电物理续程时，承诺后缀可优化，只受逐台最短时间与日末边界约束；不能顺带把原来仅窗口内锁定的DA/ID台数扩大为整日硬锁。sced 的承诺后缀同样可优化；存在日电量物理续程时与它连接。
- 纯承诺后缀只证明存在时间逻辑上的延续，不证明未来水量、功率、网络、备用或尚未进入硬域的参考台数一定可行。不能把它标成未来全资产可行证书。
- 下一窗口仍从真实执行状态重算，允许修改未执行的后缀；上轮后缀既不是执行命令，也不是已履行的时长。将来进入主窗口的参考若与真实剩余承诺冲突，必须阻断/显式重计划，不可改年龄或放松约束。未执行的后缀不能作为提前兑现承诺的依据。

完整剩余日的仅承诺后缀比精细截断到 max(ut,dt) 更容易审计，也避免后缀末又留一个未记账的承诺。性能应测量；若需要优化规模，可在同一可行域证明和穷举对照通过后再压缩，不能先省掉后缀边界。

### 6.3 与既有日电量下限续程合并

`hydro_daily_energy_suffix` 的主窗口以后每个时段必须增加 `sum_i u[h,i,k] = sum_z suffix.delta[h,z,k]`，u 必须来自上面的同一个承诺块。后缀 delta 与 stable-zone/power/water 继续使用现有物理约束。

禁止出现：主窗口使用新最短时间，而下限后缀为了凑发电量自由反复启停；或两个后缀各自有一套 u，承诺证书与电量证书由不同机组轨迹完成。

当没有日电量下限或下限已完成，承诺后缀仍存在。不能让最短时间是否生效取决于 e_day_min 是否配置。现有“参考续程软终态”仍只是软偏好，不能替代硬启停逻辑。

### 6.4 跨日 carryover 不是首版假装支持的开关

若用户不接受日内完成的保守边界，实施前先扩展运行契约：

1. 输出日末每台 online、精确/下界持续时间、剩余开/停承诺、时刻、编号、参数版本、输入/执行链 hash。
2. 下一日 DA/RT 必须消费该真实终态，验证日期相邻、无遗漏执行段、编号未换、参数变更政策及库容/功率连续；必须走独立实际状态入口，而不是默认 `initial_state(cfg)` 重置。
3. 对跨日未完成承诺保持原始 obligation 的 required-until 时刻；降低次日 ut/dt 不能追溯豁免昨日已承担承诺。
4. 若要宣称跨日水电物理可行，还需要次日来水、稳定区最低出力耗水、梯级到达等边界数据与相应后缀；仅有 on/off 延续无法证明这些。
5. 验证断点恢复与两日连续执行，未完成此前不开放“已支持跨日”的产品承诺。

仅导出剩余时长而不要求下次消费，是记录，不是约束。当前架构不满足这条完整链，因此首版关闭该模式；也不能把前一天旧运行的总在线数填成新一天的已满足时长。

## 7. DA、ID、RT 的连续状态和参考交接

### 7.1 真实状态契约

在 `SysState` / `DACase.init` 增加 `hydro_commitment`：完整覆盖启用新版的各站各台，包含 online、elapsed_h/kind、state timestamp、model/schema version。`hydro_online` 保留为兼容派生量，读取时双向核对，不再作为真实承诺状态来源。

- `initial_state`：只消费明确声明初态；缺失不猜。
- `make_window_case`：要求 state.t、时刻、cfg 网格、单位集合、输入 hash 一致，深拷贝实际状态；不得回退日初/参考状态。
- `snapshot`：保存主窗口逐台 u/s/d、初态来源、承诺尾部、是否执行。以全精度规范格式持久化，不用4位小数CSV恢复实际时长。
- `advance`：只读正式 energy_sced 的 k=0。一致状态加 Δh，状态变化重置为 Δh；核对 s/d 与转移一致，核对台数与 delta 一致后提交。更新应原子化，失败不推进 state.t。
- `state_from_plan`：继续仅用于测试/诊断，必须从已标注的初态逐段重放逐台轨迹；缺逐台轨迹时报错，不能从 delta 生造。结果必须保留 `source=assumed_plan_execution`，不能冒充实际执行。
- `_abs_plan`、ID轮次、输出恢复：逐台计划按绝对时段保存，未覆盖前缀要显式 unknown 或已有值，不能默认为全停0。

### 7.2 DA/ID 参考不会覆盖真实年龄

默认保留既有“锁定稳定区台数”语义，而非额外强制锁定 DA/ID 的逐台标签。RT 可在真实逐台初态和最小时间约束下选择哪些符合资格的机组实现相同计数；这是求解出的身份分配，不是从总台数反推历史。站内同质使这一选择合法。

DA/ID 自身也输出逐台承诺，便于审计；它们是计划，不是后续实际时长。跨市场阶段允许重新排未执行计划，但同一窗口 SCUC→energy_sced→aux 不允许重选身份。

水电参考成包验证至少覆盖：Vh、Qout、delta、价值来源、模型版本、unit ID 集合、ut/dt hash、初态来源/时刻与逐台计划的有效性。缺字段、长度不符、非法整数、轨迹自相矛盾时整站回退策略应明确记录，不能混合一轮 ID 的库容和另一轮的承诺。

ID 新参考在其轮次时刻必须基于真实 state；参考中进入本轮主窗口或既有日电量物理续程硬域的总台数需要经承诺块验证可延续。未进入硬域的更远参考不自动升级为执行承诺。如果最新 ID 不完整，原有回退 DA 的流程仍可触发，但进入硬域的 DA 参考也必须与此刻实际承诺相容。若不相容，报出站、机组、锁定要求与 earliest_switch_time 后阻断，不可强制覆盖实际状态、自动解锁参考或软化最短时间。

### 7.3 两个典型跨窗例子

1. RT 0 首段启动 A，ut=0.6h、Δh=0.25h。即使该窗口后7段安排 A 继续开，也只记已开0.25h。RT 1 还必须开0.5h网格时间；RT 2 开始时已开0.5h仍不能停，RT 3 开始时0.75h才可停。
2. ID 在时段4给出未来总在线1台，实际 A 刚启动且 B已停够时间。若切到该参考不会要求 A 立即下线，RT可延续A；如果参考下一段总数0而A剩余锁定0.5h，则当前参考不可执行，不能把A的时长改成ID计划内的长在线年龄。

## 8. SCUC、energy_sced、辅助定价的一致性

- 在 `scuc.build_model` 建唯一的承诺块，各DA/ID/RT入口都调用同一代码和同一输入验证。
- 将 u/s/d 的主窗口和后缀全部加入 `integer_components`。`fix_integers` 必须检查接近整数的可行值、记录原值/固定值，转为固定实数；不能允许未求得可行解的 None/NaN 被补0。
- 检查硬编码 `INT_VARS` 的全部调用者，特别是 `regulation.clear_reservations` 和 DA阶段比较：改为能覆盖嵌套新块的统一枚举/注册，而不是只新增一个固定函数。阶段快照用完整限定名，防止嵌套 u/s/d 与火电同名覆盖。
- 正式 energy_sced 保留全部时间、初态、台数连接和后缀约束。整数固定后它仍是 LP，连续站级出力可变，不能因此改变承诺身份。
- 水处理/弃水去退化必须保持新承诺和正式功率边界；不能从次级水处理拷入另一套整数。
- aux 从完成的正式 SCED 克隆，所有新整数固定且与正式值一致。`rt_tracking_policy=remove` 只移除既有目标跟踪，不得移除承诺块、初始剩余时间、日末完成或日电量后缀中的承诺连接。
- aux 故障不得触发物理最短时间软化；不得回退一个未经标注的价格后继续声称完整成功。保持现有阶段错误处理与价格来源政策。
- 未引入水电启动费、停机费、空载费；s/d 首版只是技术事件变量。不能擅自把火电启动费按水电套用。若将来加费用，应另行定义参数、单位和真实消费。
- 结算量、库容、功率、启停历史和持续时间只来自正式SCED；aux只提供按当前规则选定的价格。固定整数SCED对偶不是非凸承诺总成本的完整回收价格，不能宣称新增最短时间后所有启停成本均由LMP补偿。

## 9. 历史缺失与迁移政策

### 9.1 向后兼容与不可悄悄变更

- 没有新 schema/mode 的旧场景仍可按 `legacy_aggregate` 读取和复现；旧结果、冻结输入不回写、不重新解释为已施加最短时间。
- 新场景默认目标可以是 `unit_duration_v1`，但缺初态先阻断运行，而不是套模板已开/停1h。
- 旧场景更改 ut/dt 若要声称生效，必须先明确迁移。旧版编辑入口不允许显示“约束已生效”；可只读展示历史值并提供“启用最小开停约束”入口。
- 切回 legacy 是一次明确的模型模式变更，必须显示将不约束水电最短时间并保存新场景/新输入版本；不能当求解失败自动降级。
- 新旧模式可按站独立过渡，但所有运行输出按站报告 active/not_active。不能只要一个站启用了就在全局写“水电最小开停时间已启用”。首版默认场景应在全部启用站完成迁移后再作为正式新版默认发布。

### 9.2 初始化选择

优先：用户提供逐台当前在线状态、连续已开/停时长（可追溯记录或明确研究声明）。若提供 last_switch_at，用运行起点换算并核验时区、未来时刻、状态及日志。

备选：知道逐台当前状态，但历史持续时间未知，用户明确选择“保守初始化：从运行起点至少再保持一个完整最小开/停时间”。保存 `elapsed_kind=lower_bound, elapsed_h=0` 与明确选择记录，而非宣称刚刚真实启停。此方案可能使系统不可行或改变成本，预览应列出每台最早允许切换时刻。

若只有总在线数：默认阻断迁移，要求补每台状态映射。纯研究场景可以由用户明确声明一组同型模型机组编号与在线分配，标为模拟初态；不能自动把“前n台在线”冒充真实历史。当前 H1/H2 配置不足以自动选 exact 或成熟初态。

历史结果只含聚合台数时：可保留/查看；不能作为 strict 模式续跑初态。即使总数连续相同，也不能确定期间是否换机。除非另有完整逐台日志或用户确认保守初始化，不支持从该旧结果无缝恢复 strict 运行。

### 9.3 运行和编辑的一致性

- 运行开始前冻结模式、ut/dt、逐台ID/初态、网格；UI保存对下一次运行生效。
- 增加/删除水电或改变台数，必须同步提供逐台ID和有效初态；已有运行引用的ID不得重用。
- 调整当前存档的 ut/dt 后若从已有执行状态接续：第一版直接阻断“不同参数版本的中途续跑”，要求新模拟起点/重新声明初态；不要默认为修改可以追溯豁免已承担承诺。
- 若以后支持在线规则变更，旧事件的承诺截止时刻必须保留，增加最短时间如何适用于当前状态要有明确规则。这是后续独立范围。

## 10. 前端最少必要说明与反馈

建议高级设置内仅显示：

- 最小开机时间（h）：每台启动后至少连续在线多久；不足一个时间步按后续可用边界满足。
- 最小停机时间（h）：每台停机后至少连续离线多久。
- 初始状态表：机组编号、在线/停机、已持续小时、数据来源/精确或保守下界。
- 生效范围：下一次运行；DA/ID/RT共用；历史结果不变。
- 日末边界：日内完成（当前版）；需要跨日承诺时不能选择虚假的已支持选项。

保存预览给一张简短变更表：旧值→新值、哪些站生效、每台最早可切换时刻、未满足初态项。输入合法只代表可构建约束，不代表全网一定可行。保存成功与求解成功分开显示。

运行结果主界面不必长篇解释，只给“约束已启用/旧版未启用/初态待补”的准确状态。详细证据折叠展示，失败消息必须指出具体站、机组、参考时刻和冲突，不能只有泛化“不可行”。

## 11. 建议实施顺序与文件触点

所有实施应在独立副本/分支进行，先完成 Page 确认。禁止直接改当前正在验收/运行的 final_repo 或其他任务树。

### 独立审计要求

审计器从冻结输入与初始逐台状态开始，以按绝对时刻排序且无重复的实际首段逐段重放。每次状态变化，计算上一个状态的持续时长；不使用模型导出的“已满足”布尔值。验证每段sum(u)=sum(delta)、s/d正确、初始P稳定域、转移允许、最终政策。前缀最后一个尚未完成的状态记为pending，不误判已经完成，也不把尚无反向转换的合法持续状态误报为一次结束的短周期。

另对每个计划窗口与承诺后缀验证时间约束和日末边界，和执行审计分开。正式SCED、aux的新整数按完整限定索引比较；阶段价格可以不同，承诺不得不同。对存在 lower_bound 初态的结果标记“在声明下界下的保守可行性”，不伪造历史精确值。

### 推荐验证层级

1. 纯逻辑/输入/推进单元测试，不启动大模型。
2. N=1–3、时段4–8的二进制穷举参考校验：枚举逐台序列独立检查时长，与Pyomo可行集一致；覆盖0、非整倍数与残余时间。
3. 微型求解模型验证反例、绑定效果、固定整数LP/aux。
4. 现有水电初态、爬坡、价值法、下限、辅助价格、交接、输入恢复、结算测试全部回归；`python -m pytest -q tests/` 全套在独立实施树执行。
5. 完整日DA+RT及有ID的运行，使用冻结输入与独立验证脚本重放；记录gap/预算/软约束。对新增约束不设任何“应急软化”路径。

## 13. 风险、阻断条件与发布门槛

主要风险：逐台二进制增加对称性和求解负担；初态保守化导致更高成本或不可行；日内完成的边界偏差；旧DA参考在真实承诺下不再可行；现有聚合爬坡不能证明每台实际出力路径；同名嵌套变量遗漏；电量证书与承诺证书脱节；辅助模型删错块；浮点/四舍五入缩短时长；输出只写字段却没有重放证据。

不可用全局 `u[1,t]>=u[2,t]` 之类排序对称破除跨不同初态年龄的机组，否则可能去掉合法安排。优先不加破对称；如需加，只对相同技术/初态且可证明交换等价的完整轨迹类使用，并穷举对照。

下列任一情况阻断 strict 构模/执行或发布：

- 没有明确逐台状态/持续时间来源；总数试图冒充逐台历史。
- 实际 state 时刻、单位集合、参数版本、网格或已执行前缀不连续。
- 初态功率不在稳定区聚合可达域，或逐台合计与在线总数不符。
- 参考固定计数与初始剩余承诺/未来最短时间冲突。
- 配置要求跨日carry，但没有可信的跨日消费链。
- 主模型/后缀/正式SCED/aux任一阶段遗漏约束或有未固定整数。
- 新测试、完整日重放、或必要原回归没有完成；不能用当前其他任务验收结果替代。

发布定义：参数从UI/YAML进入冻结输入→模型约束→正式阶段→实际首段状态→下窗/ID→独立审计全部有证据。只改保存、只测编辑回读、只增加输出列、只在DA实现、只展示“已启用”都不合格。

## 14. Page 需要确认的两项实施前选择

1. 是否采用“逐台承诺 + 保留站级功率”作为首版，并保留明确的聚合爬坡/同型机组限制。

默认H1/H2初始逐台历史也需在启用时给出或显式选择保守初始化；本设计不替用户编造历史。确认前只完善设计文档，不实施模型约束。
