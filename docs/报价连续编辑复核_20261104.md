# 电厂报价员连续操作复核（2026-11-04）

基于 `fb6f0ad` 的独立工作树，按报价员实际顺序使用 Streamlit AppTest 控件，并启动真实后台 HiGHS 计算。没有修改出清模型、备用政策或默认求解参数；运行时限仅在独立测试场景临时设为30秒。

## 发现并修复

### P1：连续改价时，第二次修改会被丢弃

打开 C1 报价表，连续把第一行价格设为 `-1000 → 0 → 7 → 8 → 9`：

- 修复前草稿依次成为 `-1000 → -1000 → 7 → 7 → 9`。错误价格修回正常值后，仍显示原违规且不能运行；正常连续改价同样会丢失第二次修改。
- 原因是 Streamlit `data_editor` 的标识包含输入表格。第一次编辑更新了报价草稿，但屏幕控件仍基于旧输入；下一次编辑遇到变更后的控件标识而被重置。
- 现在每次表格编辑自动保存后，立即完成重新渲染，不等下一次用户操作。修复后上述五次修改逐次保存，界面、当前报价JSON与运行按钮状态一致。
- 同样保护历史分状态启动费表。新增回归覆盖燃煤、联合循环、燃气轮机、水电、风电、光伏、电池、抽蓄八类资源的十种买卖曲线，以及新增/修改/删除报价段和刷新恢复。

### P2：填写前看不到本场景的报价限制

报价表现在直接显示从校验器同一配置读取的上下限、允许段数、递增/递减、价格步长及相邻价差。火电明确指出第一行 `0～Pmin` 是内部最小出力块、不计市场段数、其价格仍进入优化；显示实际最小市场段宽及需要覆盖的容量。报价边界与结算电价边界分开说明，买入报价标明购电意愿。

说明读取资源类型覆盖配置，不把本次默认值硬编码成所有场景规则，不改变校验及模型行为。
