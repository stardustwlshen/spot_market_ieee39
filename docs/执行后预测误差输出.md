# 执行后预测误差输出

该诊断在求解和实际执行结束后运行，不参与预测、报价、优化或现金结算。读取同次冻结的 ForecastFrame/SelectedInputs 和已执行 RT 首段输入，不读取未来 actual 全轨迹。

实际值是风/光**可用功率**、系统负荷与当地自然流量，不是机组中标或发电出力。首段 actual 来源明确为 `current_interval_perfect_measurement` 研究假设。RT 预测值取该时刻发布的**原始 ForecastFrame**，不能取被首段完美观测覆盖的 SelectedInputs 而声称预测误差为零。

纯函数 API：`post_execution_forecast_diagnostics(evidence)`；evidence 是同次 `hydro_window_evidence.json` 的结构，含 `da`、`rt_windows`、`id_rounds`、独立 `causal_input_registry`、`project_timezone`。返回 status 及 actual/detail/summary 三个 DataFrame。`write_post_execution_diagnostics(evidence, new_output_directory)` 写以下四文件。正式 `write_full_outputs` 只对 v3 调用；旧模式不改原误差文件口径。

- `executed_input_actual.csv`：每资源每已执行段唯一一行。字段 operating_date、resource_id、kind、unit、period、valid_start_utc、valid_end_utc、actual_input、actual_source、selected_inputs_hash。
- `forecast_error_detail.csv`：operating_date、stage、window_start、resource_id、kind、unit、issue_time_utc、valid_start_utc、valid_end_utc、period、lead_midpoint_h、lead_bucket、forecast_input、actual_input、error_actual_minus_forecast、absolute_error、squared_error、forecast_id、information_set_id、actual_selected_inputs_hash。
- `forecast_error_summary.csv`：stage、resource_id、kind、unit、lead_bucket、forecast_comparisons、unique_executed_periods、mae、rmse、bias_actual_minus_forecast、actual_mean_unique_periods、nrmse_by_executed_mean。
- `forecast_error_status.json`：schema_version、model、valid、status、errors、范围/统计说明；成功时额外含 operating_date、day_start_utc、executed_periods、expected_periods、resource_count、actual_input_rows、forecast_comparisons、full_day、publication_windows。

MW 或 m³/s 由 unit 标明；绝对误差和 RMSE 使用相同单位，squared_error 是该单位平方。误差符号为 actual − forecast。lead 是有效区间中点减 issue，桶为 0–1、1–4、4–12、12–24 小时。operating_date 从保存的项目时区得到，不用浏览器时区改写日界。

只比较已选发布有效范围与已执行连续前缀的交集，未执行未来段完全排除。一个执行段可被多次发布预测覆盖；每个阶段/资源/lead 桶中对这些预测—目标对等权统计，不把重叠比较次数当额外执行段、能量或结算量。`lead_bucket=all` 是该阶段/资源的整体统计，与分桶行并列展示，不再合计二者。归一化分母是该资源独立实际执行段的均值；均值为零时留空，不能填零准确率。

DA 对实际曲线直接读取 detail 的 stage=DA；RT 可按 issue 选择原发布预测，actual 曲线来自唯一实际输入表。风光标题必须标可用量；自然水不得含上游受控来水。界面展示分资源误差，不混不同单位求平均。

status.valid=False 表示缺来源注册表、缺当前测量、时区缺失、执行段有空洞、哈希不符或其他无法核验的资料，表为空且 errors 说明原因，不能补零。真正只执行前两个时段的调试前缀可以 valid=True、full_day=False，必须显示实际覆盖范围。旧档若无 project_timezone，只有从其原冻结输入包核实并在独立新报告目录显式提供后才能回算，不猜时区、不回填旧档。

普通 v3 的原 `forecast_accuracy.csv` 仍不再伪装旧四阶段实际预览指标；本组四文件是完整运行的执行后误差入口。哈希核对证明选中来源与发布档一致，不是传感器真实性、在线提前可观测性或模型校准的证明。
