# 严格复核：交接与备用边界修订

基线为已发布 main 提交 abd1cb7（完整树 d91869412548743db373ba5aada1e590d952fe37）。本轮在独立副本中修订，不改已保存场景、历史结果、默认报价、成本或物理规则。

## 已复现问题与设计

1. 单个库存平衡对偶缺失会使整轮日内价值被丢弃，完好资源也改回日前；对偶为 None 则直接异常退出。保持“逐主体轨迹与价值成包”的既有交接原则：SCED 价值提取保留严格默认入口；仅日内交接显式收集逐主体的缺失、非数字、非有限对偶错误。受损主体的轨迹、价值及水电台数/出库共同回日前，其他有效主体继续引用该日内轮，并在参考元数据保存具体失败原因。不得用旧日内价值拼接或补零。非预期程序错误仍抛出。
2. intraday.lead_issue_periods 未校验，负值可读取未来发布时点，小数/布尔/字符串会被强制取整。启用日内时在准备入口校验；直接调用日内轮也在计算前校验，要求非布尔、有限、非负整数。0 保持有效。该改动仅拒绝无效配置，不改变默认提前一段的时间顺序。
3. 无火电/水电/抽蓄时，即使不含最大单机事故项，备用需求计算仍对空集合调用 max。无所列常规单机时 max_unit 明确为 0；include_ctg=False 不加事故项，True 时仍按已配置 n1_loss_mw 与 0 取最大值。负荷与新能源误差备用、上下备用开关不变，不擅自添加储能/风光故障规则。

## 验证要求

逐主体缺失/None/NaN/Inf 对偶，完整对偶及严格入口；有效资源不被污染，水电成包回退；非法/有效发布时间参数在预检和直接调用两入口；空常规集合、显式 N-1、事故项开关及原正常机组组合。新回归必须先在原基线证明失败，并在修订后通过，再运行既有交接、终态价值、备用和全套测试。当前默认真实全天结果另行验证，不以历史 da_result 夹具替代。

## 追加的输入与报告边界

独立反例还发现未知 renewable.profile 被静默套用光伏形状、上传布尔曲线被转成 1MW、零负荷加权均价产生 NaN。修订保持既有三类 profile 枚举，只在全局物理预检和曲线生成入口一致拒绝非法枚举/资源类型组合；上传数值转换前拒绝布尔单元格（包括混合 object 列）。零权重均价是“不适用”，输出 null 而不是 0 或非标准JSON NaN。小时均值与21点后统计使用实际 dt；短前缀没有21点后统计时同样输出 null。无负荷时段不计入负荷加权价差统计，并报告可定义时段数。
