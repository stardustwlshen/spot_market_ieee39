# 结算与利润时标衔接修订

## 可计算反例

原main abd1cb7的 `settle` 使用RT列表位置，而不校验每项明确的 `t`。构造两个真实求解时段，负荷分别40、100 MW，两节点、线路50 MW，源端/本地机组报价分别10/700元/MWh，步长15分钟。日前和实时按同一时刻完全一致，偏差结算理应为0。

仅将有效RT记录顺序从 `[0,1]` 改为 `[1,0]`，保留每项原来的t、真实数量和节点价格，旧结算会把错时量价对齐到日前：LOCAL凭空增加8625元实时偏差收入。因为同段供需仍平衡，账务对账残差仍是0。旧利润入口也接受，固定边际成本均1元/MWh、其他成本0时，总经营利润从8940变为17565元。

正常 `run_rolling` 按顺序追加，没有证据表明默认完整运行自动触发该问题。此为重放、恢复、低层调用或内存证据异常时的衔接防护缺陷。对账恒等式不能证明时标和来源正确。

## 修改

1. 现代RT记录必须明确使用非布尔整数 `t`，形成唯一、有序、连续的 `0..T-1` 执行前缀，不能超出日前范围。乱序、重复、缺段、部分缺少t均立即拒绝。
2. 不自动排序，以免掩盖初始状态与执行记录之间的错配。提供带t的实际初始状态时，状态时标逐项匹配；利润入口独立执行同一检查。
3. 为保留旧低层微型测试，只有所有记录均无t时，结算允许经过完整数量/价格校验的原序位置兼容，并显式返回 `legacy_positional_all_records_without_t`。利润计算不接受无t记录。正式运行仍使用完整显式时标。
4. 结算前检查资源和节点全集、数量/价格维度和有限性、非负功率/负荷松弛、切负荷不超过需求、所用价格确为原始价格按配置限价截断。合并要求一对一；仅真正缺席的零负荷行可补零，不再让坏数值被泛用fillna吞掉。
5. 当利润输入带现代数量/价格字段时，重新校核 `DA量×DA价×dt` 和 `(RT量−DA量)×RT价×dt`，并把每个主体的带符号RT结算量与真实执行首段量直接比较。储能/抽蓄充电负号独立保留。旧无量价字段的低层金额测试兼容不代表现代证据可以缺字段。

## 验证与范围

新增真实求解回归证明正常零偏差现金为0、利润8940元；错序反例被两个入口拒绝，不再生成虚假金额。还覆盖伪造金额但维持DA+RT=总额、伪造量价现金但不对应实际出力，以及混杂时标、状态错序、非有限值、资源缺失等异常。

价格公式另以真实模型的负荷微扰验证，覆盖正/反向线路拥塞、标准SCED/独立辅助LP、15/30/60分钟。它验证对应固定整数LP的边际导数，不声称整数启停的全局边际成本、实际省级市场规则认证或AC/N−1安全。历史存档现金补算的文件证据范围另由其原校验负责，本次不重写任何历史结果。
