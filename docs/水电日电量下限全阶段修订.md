# 水电日电量下限全阶段修订

状态：先记录方案，待同一方案 Page 同步并核验后实施。本文不是通过验收的声明。

## 授权与范围

用户明确要求已配置的水电日电量下限同时适用于日前、日内和最终实际全天发电量。`e_day_min: null` 仍表示不设下限；本次不猜测或新增任何默认数值，不改历史输入快照。径流式既有“不设日电量”的范围保持不变。仅库容型、非空下限启用本机制。

原实现仅在日前建立日电量下限，日内和实时均未继承。四段微模型已复现：同一下限40 MWh，日前发电39.999999 MWh，日内仅15 MWh。该问题不影响下限为空的默认场景，但不能继续把已配置下限描述为实际全天保证。

## 实际累计与剩余需求

令 `G_h(t)=Σ_{k<t} P_h^exec(k)×dt`，只累计每次实时正式SCED首时段实际发电，不累计日内计划、实时预测窗口或后缀见证量。剩余下限为 `L_h(t)=max(0,Emin_h−G_h(t))`；剩余上限沿用 `U_h(t)=Emax_h−G_h(t)`。滚动初态携带实际累计量，不能用日前累计量替代、重置为0或从缺失值猜测。

日前约束全日发电不低于已声明下限；日内窗口覆盖剩余全天，直接约束其发电量不低于L。实时窗口覆盖日末时，也直接约束窗口剩余发电达到L。已经超过下限时，剩余下限为0，而剩余上限仍有效。

## 实时提前保护

只在已配置非空下限、尚有正剩余要求且实时窗口尚未覆盖日末时，附加水电资产级剩余日续程证书。显式0和已经完成的下限保留配置与审计记录，不额外建立续程，不意外收紧原物理可行域。当前市场窗口仍为原2小时，仅执行首段，不把市场扩为全天。

1. 续程从当前窗口末的实际优化库存、出力、在线台数连续到日末，保留水量动态、物理库容、生态流量、出库上限、报价可供量、稳定区整数台数和站级爬坡。梯级关联站一并纳入，以同一时滞读取当前窗口变量、续程变量、已执行历史或既有日前前史假设，不使用未来实际值。
2. 当前窗口加续程的合计发电满足所有已启用水电的剩余上限，以及声明下限资源的剩余下限。实时锁定参考台数的模式，续程沿用本轮同一DA/ID参考台数；固定日前功率模式同样沿用对应日前未来功率；自由水电模式保留可行整数台数决策。日内无结果时沿用既有来源回退语义，实际累计不重置。
3. 续程只证明水电资产在该参考下仍存在满足日电量下限的物理续程，不能声称未来网络、备用或全系统联合可行。它没有未来电能报价目标，也不产生未来结算。原水电有符号价值、参考续程软目标成本和日末软目标政策均保持；证书不额外强制日末库容等于目标，不借此把soft改回hard。
4. 正式SCED固定续程的全部整数。辅助定价默认保留证书；显式移除跟踪不能删除日电量物理边界及证书。硬带应急软化同样不得移除该下限，不能通过松弛、放宽整数、伪造累计量或给下限添加罚项绕过。
5. 证书不代表预测准确或未来全网保证。后续状态或计划变更仍可能导致真实不可行，必须报告失败。日内明确物理不可行可按既有规则回退日前参考，但实时仍须独立满足下限和证书；若实时不可行，中止并保存已执行前缀，不称完整成功。

## 独立审计和失败语义

导出每日下限、实际已发、剩余下限、窗口预测发电、后缀见证发电、合计余量、来源和保证范围；后缀标明不执行、不结算。逐轮核对实际累计连续性，不能累计重叠窗口。日前与成功日内分别核验各自全剩余范围，不把失败日内计成功。

最终日发电从96个正式执行首段重新求和，逐主体核对下限。缺时段、重复时段、缺主体、非有限值、实际累计不符，均不可判通过。短前缀只能报告目前已发/尚缺，最终日下限合规为未完成，不得把当前未达判作全天成功。完整运行若不足，明确失败并保留证据；账务闭合不替代日电量合规。

## 验证计划

- 原40 MWh微模型：日前、日内和最终实际都达到下限；已发15时日内仅要求余25，已发超过下限不重复要求整日下限。
- 提前透支水量/关机的反例：无后缀可短视进入死角，新证书应拒绝或提前安排出力；物理不可能的下限须明确不可行，不能软化绕过。
- 剩余上限、库容、生态、爬坡、整数稳定区、梯级时滞、跨窗实际历史及DA/ID源开关均保持。
- 续程整数固定、辅助保留和显式remove、紧急硬带回退不能删除该下限；后缀量不执行、不结算、不累计。
- 最终审计注入缺失/重复/非有限时段、缺主体、累计不符和真实短缺，确认失败或未完成；默认null与历史场景回归不变。
- 在最终整合代码运行针对性和全量回归，并至少一组显式非空下限的完整日内+96段实时验收。没有该证据不得声称该新功能已完成全天验收。
