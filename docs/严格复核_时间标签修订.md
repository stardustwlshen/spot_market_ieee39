# 时间步长展示修订设计

合法输入包括 48×0.5 小时，不能用展示端硬编码将支持范围缩为 96×15 分钟。模型输入校验保持原职责；本修订不改变出清算法。

统一以每次运行冻结配置的 dt_h 和 periods 生成时刻、窗口分钟数和 MW→MWh 换算。历史结果优先读取 scenario_snapshot/config/base.yaml，再读取保存的 summary；仅无时间元数据的历史档案保留原 15 分钟兼容默认，不以实时已执行行数推断全天步长。无效显式元数据报错，不静默回退。

结果页、明细筛选、价值浏览、网络选择和静态图传递同一时步。跨不同时间网格的对比不按相同时段序号伪造对应关系。预测输出 time 列也按配置生成。图形时间轴截断范围仅影响显示长度，不改变步长。

聚焦测试覆盖默认15分钟兼容、48段半小时时刻及末点、冻结配置优先、截断实时窗口、电量换算、图形刻度与预测输出。

## 验证与范围

聚焦回归：时间网格、调度明细、最终结果口径、预测设置、价值参考 UI 共 87 项通过；compileall 与 diff 空白检查通过。新增测试文件为 tests/test_time_grid_presentation.py。

本次明确支持并验证完整24小时的48×0.5小时与既有96×0.25小时展示。预测日周期形状目前按24/T生成，T×dt≠24的非整日输入仍需单独建模审计，不能仅因标签修好而声称支持。历史无冻结时间数据的默认兼容并不构成证明其实际时间网格的证据。

## 完整日与短微模型的边界

生产 prepare 入口要求 periods×dt_h=24，允许48×0.5小时等一致网格；短段调试仍用 --periods 截断执行，不把半日配置压成全天。底层单段/短窗模型仍用于算法测试，不新增全局24小时限制。输出完成标记在获知 dt_h 时也核对实际日长；短物理时域不能因执行数等于配置数而称全天已结算。历史缺少步长元数据继续按原记录解读。
