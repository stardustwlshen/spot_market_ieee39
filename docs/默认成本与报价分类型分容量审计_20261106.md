# 默认成本与报价：类型、容量与计量口径审计

日期：2026-11-06。范围：当前工作树的 IEEE39 新默认、机组新增/复制、成本预览、核算成本。**本文件是审计和待实施方案，不代表已经采用新的默认数值；未改报价版本、成本档案、求解器或历史场景，未推送。**

## 1. 结论

用户提出“默认的报价还是要考虑不同类型不同容量机组的成本不同啊”是当前默认机制的实际缺口，而不是只需要修改显示文案。

1. 当前 `default_bids()` 只按大类给固定价格。煤电 C1/C2/C3 的不同容量只影响 MW 分段，价格全部相同；风光也是同一组价格；电池和抽蓄也没有从各自效率和成本生成默认价格。
2. 当前最新仓库报价 v4 并非统一成本基准。它保留 v2 的演示改价：CCGT 加价150元/MWh，ES2优惠报价，再追加新光伏和新电池。保留历史版本正确，但把它继续作为“新版默认成本报价”不合适。
3. 已有“按成本生成”能够使用 C1/C2/C3 各自280/297/315元/MWh的档案，所以可以先复用正确的分离架构，不必重写出清模型。
4. 新增资源的 `generate_research_defaults()` 只对火电在线/启动总额、抽蓄单台启动费作容量缩放。煤电边际成本统一280，风电统一8，电池退化成本统一25。显式采用“替换已知研究成本”时，还会把原 C2/C3、W2、ES2/ES3 的差异抹平。它不是无条件自动覆盖用户档案，但生成逻辑本身不足以满足新的目标。
5. 新增火电的技术模板另有不一致：煤电、CCGT、GT统一使用在线费10元/(MW·h)、热态启动费400元/MW；成本生成器却按各自类型的参考机组缩放。报价预览只改能量价格，不改这两项，于是新增燃机的默认启动报价会远高于其生成的核算成本。

建议：**把新默认改成“显式成本参数 → 类型与容量适配 → 分开的报价策略 → 规则校验”的单一路径，并另存新版基准。** 原场景、历史报价和手工价格不能自动迁移。不能为了让所有显示价格都不一样而人为加随机差价。

## 3. 必须保留的成本与报价边界

### 3.1 三层分别保存

1. 技术层：类型、单机/聚合范围、额定MW、MWh、水头/耗水率、效率、最小出力、启停和爬坡。
2. 核算成本层：燃料与可变运维形成的边际成本、在线固定成本、单次启动成本；水电现金运维；电池退化；抽蓄运维与启动。它们只能由明确的成本档案或已接受的假设生成，不能从市场报价、出清电价反推。
3. 报价层：能量成本锚 + 明示的机会成本/策略加价；启动报价、空载报价各自独立。初始默认可以等于成本值，但修改报价不应修改核算成本。

费用按 `变量成本×实际MW×dt + 在线费×在线状态×dt + 启动费×启动次数` 计算。启动费不能再乘dt；抽蓄按新增在线台数计算元/台次。当前 `profit.py` 的单位处理与充电结算不重复扣除的架构可保留。

### 3.2 平均热耗和增量热耗不能混用

当前说明把 `heat_rate` 同时用于边际燃料成本和 `3.6/heat_rate` 的“平均效率”显示。只要另外收取含燃料的零输出空载截距，后者就不再是机组在该负荷下的平均效率。

推荐明确采用以下一种口径，不能混合：

- **兼容现有标量模型的口径**：把生成器热耗明示为合成的增量热耗 `h_inc`；总燃料输入为 `H0×u + h_inc×P`。空载燃料成本为燃料价×H0。平均热耗为 `H0/P + h_inc`，不能直接用 `h_inc` 宣称平均效率。在线费如还含非燃料固定运行费，另行列明。
- **以参考平均热耗校准的口径**：在指定净出力P_ref，已知平均热耗h_avg与H0，令 `h_inc = h_avg - H0/P_ref`，再形成能量边际成本。必须验证h_inc为正。

当前历史参数是独立合成标量，没有被证实重复收了某笔实测燃料费，因此本审计不把“可能的口径混淆”夸大成已发生的会计重复。但新的校准绝不能用含空载燃耗的平均成本加上同一空载燃耗。

内部0—Pmin段已经承担Pmin能量费用时，不得把 `Pmin×能量价格` 再加到空载项。市场段加价阶梯当前只是报价策略，不是实际热耗分段曲线。若以后改为分段真实增量热耗，需要同步修改核算成本积分与版本，不能只改名称。

### 3.3 储能和水电

- 电池/抽蓄放电成本报价可用 `预计购电价/回路效率 + 放电退化或运维 + 机会溢价`。购电价与机会溢价是报价依据，不是再扣一次的执行期现金成本。
- 当前算法的 `sell=max(replacement/η+expense,reservation)` 与 `buy=η×(reservation−expense)` 是明确的研究报价策略，不是市场规则要求，也不证明最优套利。保留策略名称和参数来源。
- 实际充/抽电支出已在有符号净结算收入中计入，不能在利润中又扣“预计购电价/效率”。损耗已由充放电能量守恒体现，不能再随意加一遍损耗电费。
- 水电现金运维不等于水的机会成本。机会成本应区别库容式/径流式、丰枯、可用水与期末库存，不能仅用电站MW决定。终端库存价值和显式水机会报价的组合要说明作用区间，不把两者简单相加称为实际成本。
- 当前利润排除固定资本、融资税费、年度固定运维、容量收益、调频收益、库存重估等，因此不能用LCOE或全寿命项目成本替换短期边际报价，也不能称为“项目净利润”。

## 4. 建议生成逻辑

### 4.1 参数优先级与可追溯性

优先级：用户明确逐机组成本参数 > 用户选择的技术/容量档位模板 > 有名称、有版本的合成默认。每项保存来源、日期、单位、是否假设、适用容量范围、原值、公式与最终值。相同类型/技术/容量参数的资源重命名后结果必须不变；不得用ID尾数或未固定的随机数制造成本差异。

容量要区分：火电当前一条记录的启停整体；水电/抽蓄单台MW与台数；风光可能是聚合场站；电池功率MW与能量MWh。不能把“聚合了更多同型机组”误当作“单机更大、效率必然更高”。技术未知时允许使用明示的合成代理，但要在预览提示。

### 4.2 火电：成本随类型、容量和效率参数变化

新生成器至少应让不同容量的同类型火电产生不同的**未量化成本锚**，不能只改变MW分段。优先采用用户输入的净增量热耗/技术档位。没有这些数据时，可提供以下有界、可复现的研究模板作为候选，不把系数冒称实证结论：

- 沿用当前参考点：煤电646MW、燃料30元/GJ、增量热耗9GJ/MWh、VOM10元/MWh；CCGT687MW、60、6.5、15；GT300MW、60、10、20。
- 研究容量修正示例：`h_inc(P)=h_ref×clip((P/P_ref)^(-0.08),0.90,1.15)`；`VOM(P)=VOM_ref×clip((P/P_ref)^(-0.05),0.90,1.15)`。
- `MC(P)=fuel_price×h_inc(P)+VOM(P)`。上述0.08、0.05和上下界全部是待采用的研究假设，仅表达同一技术族中温和的规模/效率差异，不证明真实机组随MW单调改善。参数记录必须保存修正倍率与是否触及边界。
- 在线、启动费用按类型参考额与容量比缩放，沿用现有明确公式即可作为第一版假设；报价模板的初始在线/启动值应从对应生成值复制一次，之后两份独立。不能再把所有燃机统一套用煤电400元/MW启动模板。
- 参考技术范围外需提示或要求选择模板，不应无限外推。已明确的低效大型/高效小型机组参数必须覆盖规模代理；因此历史C3成本大于C1不应仅凭容量就判成错误。

保留一个较小改动路径：先用现有逐机组280/297/315/405/620成本建立新的成本报价基准；容量修正作为版本化生成器用于新默认重建和新机组。是否统一重校准现有合成档案，是重大默认输入改变，应在Page与文档列明旧值→新值再实施。

### 4.3 风光、水电、电池、抽蓄

- **风光**：类型不同可使用不同可变运维；同类成本差异可以来自明确运维档位、技术和场址假设。额定容量改变总发电量与总成本，但聚合同一技术扩大装机不必改变元/MWh。容量经济主要在资本和年度固定运维，当前模型不含这些项，不能把它们伪装成短期燃料成本。现有10元量化可能得到相同报价，应诚实展示。
- **水电**：至少区分库容式/径流式。容量经单台尺寸、台数、耗水率和水量可用性影响运行边界，机会成本另由水情/库容策略给定。若补充水电启动/在线费用，将新增优化目标项，属于另一个模型改变，必须单独提案，不能在报价成本里暗塞重复的启停惩罚。
- **电池**：容量至少同时记录MW、MWh、E/P、SOC可用带、回路效率。退化元/MWh应来自明示的寿命吞吐量/化学体系/工况假设，而不是对MW直接乘倍数。可采用 `可替换电芯成本(元)/寿命交流放电吞吐量(MWh)`，总成本和吞吐量均随能量容量变动时单位退化费可以不变。若为2h与4h设不同退化档位，须说明C-rate或寿命参数差异是研究假设；没有这些依据时不建议硬规定4h一定更便宜。
- **抽蓄**：按发电/抽水单台功率生成不同的启动费，分别乘实际新增台数；按能量转换效率决定补电成本。单纯增加同型台数应增加总启动费用和MW/MWh，不应把每MWh运维再乘台数。

建议预览同时列示“单位成本差异”和“在相同负荷率/运行小时下的总成本差异”，避免把所有容量影响压成同一条元/MWh公式。此处是在落实类型与容量差异，不是要求所有资产的电价必须互异。

## 5. 集成顺序和保护边界

1. 先把本审计与明确的新默认数值方案同步到现有Page，记录用户目标、成本口径和历史保护边界。
2. 将类型、参考容量、热耗、运维、在线与启动参数集中为一个可审计模板。`unit_template`、成本生成、成本报价预览不得分别维护互相冲突的默认费用。
3. 新版本生成器负责按技术参数生成成本档案和依据；`default_bids`的新成本模式只负责从已有成本与机会参数生成报价。保留旧显式历史模式用于历史回归，禁止无档案时默默回退成“成本报价”。
4. 新建“成本基准默认”只另存新版本，不再继承v2演示加价；旧v1—v4、旧场景、手工草稿与历史输出不改。复制旧场景仍保留其原始报价。预览/采用必须只作用于用户选中的资源，保护手工修改。
5. 现有生成叠加档案的读取器要求算法版本严格匹配。若把 `typed-research-defaults-v1` 改为v2，要显式兼容旧v1记录及其哈希，不能让旧场景因新版本而打不开，也不能把旧生成结果静默重算。
6. 先做纯函数与UI测试，再运行新默认的DA+RT96及丰枯/高风光/负荷角点。报价改变会改变启停、储能行为、水的边际价值、出清价格和利润；旧基准的求解成功不能代替新默认验收。

代码定位：`src/smm/bids.py`的 `_thermal_default/default_bids/pumped_default`；`src/smm/research_defaults.py`；`src/smm/research_cost_setup.py`；`src/smm/bid_simulation.py:research_cost_bid_preview`；`src/smm/unit_editor.py:unit_template/prepare_unit_edit`；`src/smm/profit.py`；`src/smm/scuc.py:_objective_expr`。新增默认场景路径是 `src/smm/scenario.py:create_scenario`，当前会复制仓库已有报价。

## 6. 验收要求

- 同类型不同容量的火电未量化成本锚有明确差异；技术、热耗覆盖优先；同参数改ID不变。
- 复制更多相同水电/抽蓄机组只按台数增加对应总量；不把元/MWh按台数倍增。
- 电池MW、MWh、可用时长与损耗转换有独立测试；不将购电成本或退化计两次。
- 启动费用元/次只按事件，在线元/h乘dt，能量元/MWh乘MW×dt；改变时间步长不改变相同连续物理轨迹的成本。
- 平均/增量热耗口径明确，0—Pmin能量与空载不重复；报价阶梯不冒充实际成本积分。
- 修改报价不改变成本；修改机会价值不改变现金运维成本；所有假设可见。
- 旧场景、旧生成版本、手工报价和未选择资源保持字节级不变。预览不写入，明确采用后才形成新版本。
- 规则量化/限价不自动修改成本；超限、非单调、分段不兼容时说明原因，不暗中裁剪或修改规则。

本次只读计算验证了17资源报价预览、重命名不变性、类型/容量模板矩阵。聚焦回归结果另见同目录验收记录；本次未做新默认DA+RT96，因为本次尚未采用新数值。

## 7. 可核实的公开依据与适用边界

以下资料核查于2026-11-06，仅支撑公式、成本类别和技术差异，不支撑本项目逐机组价格或任何容量修正系数。

1. [EIA：调度与变动运行成本，2012-08-17](https://www.eia.gov/todayinenergy/detail.php?id=7590)。燃料价和转换效率影响火电变动成本；风光、水电虽低变动成本，仍受资源/水库和运行条件影响。不能据此断言水的机会价值为零。
