## 重要缺陷与处理

| 问题 | 原因与修复 | 核验 |
|---|---|---|
| 连续报价每隔一次丢失 | 编辑后输入表格变化，而控件仍用旧表身份；保存后立即重建控件 | 八类资源十条曲线逐次改错、修正、另存合法值，读取current_quote、冻结报价和load_bids一致；A→B→A及全新会话恢复互不覆盖 |
| 连续结果选择第二次弹回旧结果 | 选择器index随状态改变而重建；改为稳定控件键与独立持久选择值 | 四个真实96段档案反复切换、离页返回、明确跳转；1.979%与237.2283MW告警随所选档案正确出现 |
| 运行卡不能直接打开本次结果 | 原有输入监控选择和历史结果选择独立 | 新增“查看本次结果”，只在用户明确点击时打开该记录；不强制替换主动浏览的历史，也不改当前场景 |
| 重启中断后一直取消等待 | 未知身份不能安全释放，缺恢复闭环 | 新记录增加机器/启动会话证据，锁内复核后明确归档为失败且未结算；两记录逐项恢复，仍有其他未知占用就不能新跑 |
| 坏结果或缺表裸抛异常 | JSON/CSV读取、必要列和数值缺少统一边界 | 保留顶部选择器，中文报错、停止该档案渲染；坏JSON、缺价格文件/列、lmp与出力字符串/NaN/inf都不能被当零，可切回正常档案 |
| 仅日前结果抽蓄KeyError及均价口径不一致 | 仅日前页访问不存在RT、均价误取逐时算术平均 | 仅日前完整渲染，选已保存负荷电量加权均价；不改历史价格 |
| 运行耗时一直省略号 | 结束才记录elapsed_s | 活动状态显示“启动后约”墙钟耗时；不是纯求解耗时，终态只用已记录elapsed_s |
| TIE说明/历史曲线混用 | 总净出力含TIE却称报价主体，旧RT缺TIE时补了DA值 | 标签按实际口径；旧RT缺值不从DA补入，负荷和区外来电分开 |

报价限制现在直接读取本场景的实际校验配置。火电0～Pmin内部基座、市场报价段数、买入意愿及结算电价上下限分别说明，不新增或更改市场规则。

## 真实操作与独立复核

- 实际用界面新建五类50MW机组、修改成本报价、储能SOC和抽蓄日末水位，启动真实后台日前96点加实时8点，67.2秒完成。煤机空载432.1元/h进入模型，新电池日末SOC0.52、抽蓄日末19.75万m³均与输出一致；逐主体利润界面等于原CSV。这是明确的调试前缀，不是新增机组全天RT认证。
- 实际重复启动被拒绝。SCUC期间取消请求在计算边界生效，40.3秒后stopped、执行0段、未结算，启动按钮恢复；不以强杀实现取消。
- 最终集成树独立从真实结果页选择不利组合，再在运行页选普通基准并点击“查看本次结果”，核对目标档案、缺额警告消失、再次刷新及离页返回保留选择、当前场景和源文件哈希不变。
- 独立读取四个96段档案及新增机组8段前缀，重算每阶段节点负荷加权价、各自时域负荷电量加权价与逐时价差算术均值，和保存摘要差异只在CSV四位小数序列化量级。全日DA均价与调试前缀同范围DA均价不混用；RT权重为保存的实际负荷，不是当前配置或已供负荷。逐时价差均值通常不等于两个阶段电量加权均价相减。
- 不能取得负荷权重、已知冻结节点的价格缺行、非有限权重及零总负荷不回退成等权或零。价格表自身记录的RT负荷仍是权重，冻结节点只负责完整性，不替换执行负荷。
- 独立中断复核为61项通过及真实AppTest两条记录分别恢复；只修改meta审计字段，日志、报价、取消标记与其他输出保持原字节。没有真实重启操作系统或重算市场。

## 安全与验证边界

- 跨重启只对可信同机、不同启动会话的**新身份记录**提供显式恢复。缺身份的升级前记录、外来机器、权限不足、仍存活或证据冲突的进程继续阻止新跑，不杀未知PID，不双启。旧无身份记录不会被猜测补齐。
- Linux有实际进程/锁/AppTest验证。macOS身份分支仅模拟；Windows缺已验证启动会话来源，跨重启仍fail-closed。克隆或共享机器ID不在可信边界内。详见[安全恢复说明](运行中断安全恢复.md)。这些限制不能写成“所有平台重启恢复完成”。
- Chromium被环境socket权限拒绝，未绕过，未做像素级浏览器或下载落盘验收；Windows/macOS没有本机原生实测。
- 本轮无新的全天模型求解。此前完整模型档案仍是数值证据，用户操作改进不提高其预测真实性、网络物理范围或实际求解精度。
