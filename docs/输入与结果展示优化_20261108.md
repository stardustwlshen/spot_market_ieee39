# 输入与结果展示优化（2026-11-08）

读者：Wls。基线：`main@5c6ab3c`。本文只规定单日模拟的输入分层和结果叙事，不改 SCUC / SCED / 价值法公式、罚因子或 `config/modes.yaml` 的默认值。

## 1. 验收口径

- 不要求严格无松弛。跑完 96 段、退出码为 0、或页面能打开，都不等于备用缺额为零，也不等于软日末偏差为零。
- 备用缺额、软日末偏差、交接回退必须按已保存证据披露。缺字段写「未记录」，不用当前配置或零补齐。
- 日内市场在 `config/modes.yaml` 的 `MKT.intraday.enabled` 保持 `false`（甘肃模式：不设独立日内市场）。界面必须让人一眼看出当前场景是开还是关。研究对比要开日内时，仍只通过既有「高级参数」保存，不在本页另写一份开关。

## 2. 不改什么

- 出清模型、约束、备用公式、价值提取 `v = −dual`、软日末罚价默认值、交接成包规则、结算口径均不动。
- 单日五步（场景 → 机组 → 报价 → 运行 → 结果）和四个结果业务页签（系统总览、机组分析、价格分析、网络与安全）保留。新内容挂在这两套结构上，避免第二套可写参数。
- 历史结果目录只读。缺 `rt_value_windows`、备用系统表或日末记录时降级，不抛页面异常。

## 3. 输入信息架构

平铺长表单改为三层。编辑入口仍是现有控件。

三层不在每一步重复。场景步只强调已保存的日内开/关。机组步和报价步各留一行「已保存场景状态」。完整三层摘要只放在运行步，合约卡仍只在该步「开始」之前。

| 层 | 出现位置 | 内容 | 写入 |
|---|---|---|---|
| 日内状态 | 场景步顶部 | 已保存的开或关 | 不在这一步改。水文和误差仍用下面的选择，点「下一步」才另存副本 |
| 一行状态 | 机组步、报价步 | 日期、丰枯、日内开或关、上备用 | 不展开资源、研究开关或假设值 |
| 场景层 | 运行步 | 日期、丰枯、误差档、日内开或关、上备用 | 日内与备用只展示已保存值 |
| 资源层 | 运行步，默认折叠 | 展开即显示容量摘要；编辑仍在「2 机组」 | 不在本层保存，也不再套一层「加载」勾选 |
| 研究开关 | 运行步，默认折叠 | 价值法、锚点、软日末罚价、交接来源、GT `inherit`/`free`、日前/日内/实时 MIP gap | 只读。修改仍走运行页「高级参数」 |

场景步用独立提示标明日内状态：

- 关闭：`日内市场：关闭（甘肃模式，默认不设独立日内市场）。`
- 开启：`日内市场：开启。` 并说明只更新参考、不单独结算，且这是当前场景显式打开，不是产品默认。

已保存状态与尚未应用的场景选择分开写。未点「下一步」时，场景层和合约卡都表示已保存场景，启动按钮保持禁用。

### 3.1 合约卡

运行页在「开始单日出清」之前给出只读合约卡，至少包括：

- 日内开/关
- GT 策略（`intraday_commit_rt` 与锁定/自由类型）
- 上备用政策
- 价值法模式、水电策略、软日末模式与罚价
- 报价版本、来源、主体数
- 输入指纹（场景关键项 + 报价包的短哈希）
- 当前代码短 SHA（界面版本，不是已冻结运行的源码指纹）

必须勾选「已核对合约卡，确认按此启动」后，原「开始单日出清」才可按。指纹或运行范围变化后确认作废。点击开始的冻结、校验和启动路径与原来相同。

### 3.2 假设值

无省级规则原文唯一数值的项标记为「假设值」，并在「假设值一览」列出当前生效值与理由。固定上备用 400 MW、偏差带 2%、软日末罚价 1000 元/可放电 MWh、MIP gap、锚点比例 `x` 都属于这一类。价值法作为默认方法、日内默认关闭，分别标成研究设定或甘肃模式，不冒充假设值，也不写进假设值一览。

本轮不新增假设值，也不改 `modes.yaml` 里的数。

## 4. 结果信息架构

顺序固定，不把所有图平铺在第一屏。

### A. 可信度条（四个业务页签之上）

三项并列：

1. 是否跑完 96 段实时。只有 `completed_scope=full_day` 且已执行段数等于预期段数且预期为 96 时为「是」。仅日前、前缀试跑、段数未记录都不得显示为跑完。
2. 上备用缺额：优先读已执行实时备用系统表的 `R_up_short`，给出累计电量（有时段长度时）和最严重时段。没有逐时段表时，才读摘要里的最大缺额，并注明不是逐时段证据。
3. 软日末偏差：储能、抽蓄、水电分列。优先读 `realtime.executed_terminal_deviation_records` 的可放电 MWh；没有该记录时，才读价值窗口里标为日末的行。三类缺一不可，缺的写「未记录」。模型罚金不是结算付款。

条下固定一句：跑完不等于无松弛。

### B. 差异叙事（系统总览顶部）

关键轨迹用单选切换，不同时铺开所有曲线。负荷加权电价和弃电始终在选项里；没有保存曲线时该选项显示「未记录」，不补另一侧，也不画零线。储能电量、抽蓄上库、水电库容只在至少一侧有有限数值时才出现。

其下仍是按类内 `|Δ|` 从大到小的问题清单。类别为价差、弃电、备用缺口、SOC/库容偏离、交接回退。不同物理量不跨类比大小。选择一行后展示该时段已保存明细。交接没有回退记录时在说明里写「未发现」，不造一条假回退。

叙事下面是原来的日前/实时 KPI，不放进折叠。机制审计单独收起，避免和轨迹、KPI 挤在一起。

### C. 机制审计（系统总览内的单选页签）

不用第五个顶层页签，以免打乱既有「系统总览 / 机组分析 / 价格分析 / 网络与安全」。不另加同名标题。默认折叠；展开后用单选切换：

1. 价值法窗口末 `v`，以及软日末触碰与罚金
2. 交接来源与回退原因
3. 备用需求、供给、缺额
4. 水电日电量进度，以及前瞻触发（前瞻是参考续程偏好，不是全网可行证明）

缺表时各块独立降级。

### D. 原有阶段块

日前 / 实时 KPI 在系统总览里常显。供需、弃风弃光、系统对比、预测误差和经济结果收进「阶段结果与主体经济」，该折叠默认展开，避免第一屏只剩叙事。机组分析里的价值曲线和库存对比、价格分析、网络与安全保持原页签。经济结果仍按主体与物理量对齐，本轮不改口径。

### E. 场景对比的矩阵取向

对比页增加「丰枯 × 日内开闭」说明：四格为丰水/枯水 × 日内关/开。本次不实现一键批跑。结果少于两次时仍显示该说明，避免把空态理解成功能缺失。

### F. 导出

结果页默认不出现下载按钮。点「生成导出文件」后给出一个 JSON：可信度摘要、假设值或「冻结配置未保存」、Top 偏差、输入/源码指纹。文件名带当前界面短 SHA 和指纹缩写。这是查看器导出，不改结果目录。

## 5. 手工点验

1. 打开「单日模拟」。场景步应看到「日内市场：关闭」，且没有研究开关、假设值或资源层三块。机组步、报价步只有一行「已保存场景状态」。
2. 走到运行步。这里才有三层摘要，资源层展开后直接有容量表，没有「加载资源容量摘要」。研究开关和假设值默认折叠。合约卡为只读；未勾选确认时不能开始。`modes.yaml` 仍为 `enabled: false`。
3. 打开一份结果。系统总览先是差异叙事，可在负荷加权电价、弃电和已保存的储能/抽蓄/水电状态之间切换；缺的轨迹写未记录。KPI 在折叠外。阶段结果默认展开，机制审计默认收起。
4. 打开「场景对比」。即使结果不足两次，也能看到四格矩阵说明。

界面测试用 Streamlit AppTest 和纯函数断言。AppTest 不代替浏览器像素验收。
