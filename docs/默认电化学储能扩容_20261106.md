# 默认系统电化学储能扩容方案

状态：方案已于项目Page先行记录并回读确认后实施为候选默认配置。本文保留实施依据、筛查口径和待集成正式验收边界；不将局部测试或LP筛查写成最终96段验收。

## 1. 用户要求与改动边界

用户要求“默认系统中的新型储能可以再增加一些”，没有指定技术路线、规模或节点。本方案将“新型储能”解释为现有模型能够表达的聚合电化学储能，不把它称为已验证的磷酸铁锂、液流电池或其他具体技术项目。

只增加默认资源和相应输入档案，不改策略模型、原资源、负荷、风光、抽蓄、线路限额、日内/实时规则、价格规则或日末目标处理。已有场景、当前报价草稿、旧报价版本和历史结果均不自动扩容。

## 2. 当前系统与建议增量

当前默认本地火电3223MW、水电508MW、风电1604MW、光伏2152MW，风光合计3756MW；另有600MW抽水蓄能和1100MW联络线额定容量。默认种子产生的模拟实际峰荷4313.52MW、谷荷2772.20MW、全天负荷88419.88MWh。风光实际可用输入31799.67MWh，不等于扣除弃电后的发电量。

现有电池：ES1在19号节点100MW/200MWh，ES2在16号节点200MW/400MWh，ES3在25号节点100MW/200MWh，共400MW/800MWh。

保留原三站，新增：

- ES4：4号节点，150MW/600MWh。
- ES5：8号节点，150MW/600MWh。
- 新增合计300MW/1200MWh；电池总规模700MW/2000MWh，功率增加75%，额定能量增加150%。抽蓄容量不计入这组电池数字，且不改变抽蓄配置。

两新增站均采用ηc=ηd=0.95、SOC10%–90%、初始SOC50%、日前缺省日末申报SOC50%。效率、SOC边界与现有电池一致，容量是本项目研究假设。

600/150=4小时仅为额定能量/功率比，不是可持续额定放电4小时。每站90%→10%可输出600×0.8×0.95=456MWh，即3.04小时；两站全可用带可输出912MWh。初始SOC50%时，每站向下至10%只可输出228MWh，两站初始可放456MWh。全体电池的全可用带输出由608MWh增至1520MWh。

选择150MW/站是与各750MW聚合光伏配套的20%功率研究比例，不是法规要求、真实电站配储要求或经投资优化得到的最优容量。新增功率约为模拟峰荷的6.96%；电池总功率约为峰荷16.23%。这些功率比例不能当成可保障同等峰荷比例持续整晚的证明。

## 3. 节点依据与同条件比较

4号和8号节点已有PV2/PV3各750MW，原始基准节点负荷分别500/522MW。4号通过3/5/14号相邻节点连接；8号通过5/7/9号连接。其多路径接入与原电池19/16/25号的受限通道配置形成互补，便于研究本地光伏时移、晚峰功率和备用贡献。

已做15项同条件只读筛查：原400MW/800MWh，以及新增两站分别位于4+8、19+25、16+25、4+27四布局；每种在三场景比较：丰水基准、丰水新能源×1.2且负荷×0.9、枯水新能源×0.8且负荷×1.1。新增报价和容量相同，只改变节点；风光乘数后仍按原容量限幅。

全部15项为96段日前整数松弛LP，将切负荷、过剩、线路越限与上/下备用缺额固定0，均optimal；输入文件哈希核对未改变。这是候选筛查，不是整数SCUC、96段实际RT、事故状态或N−1安全认证。筛查使用其冻结的当前水电备用口径，不替代即将集成的新15分钟水量备用约束下验收。

结果：

- 丰水基准：原布局LP报价目标2440542.60元；扩容4+8为2417345.14元，低于同容量19+25/16+25的2426769.38元及4+27的2419614.66元。各布局弃风均651.92MWh、弃光0，不能声称扩容消除了基准弃电。
- 丰水高新能源低负荷：原方案弃风光9466.96MWh；4+8为9025.87MWh，减少441.10MWh但仍有大量弃电。同容量19+25/16+25为9214.33MWh，4+27为9078.59MWh；4+8在本次有限候选中报价目标也更低。
- 枯水低新能源高负荷：各方案均无弃风光；所有扩容布局的LP报价目标约7449087.23元，原方案7683972.32元。新增站的LP充放电量均为0，这种改善来自运行/备用容量分配，不是新增电能供给，也不是投资收益证明。
- 4+8基准新增两站日充电505.26MWh、放电456MWh；高新能源低负荷日充电432.69MWh、放电390.50MWh。不能以912MWh可用库存推出每日都满循环或必然经济合算。

这些只是有限候选、固定报价及合成日的比较，不宣称全球最优选址或最优储能规模。网络最大利用率达到1，扩容并未消除所有阻塞。没有增加任何线路限额。

## 4. 报价、现金成本和UI兼容

已新建报价v4，深拷贝v3的全部既有主体报价，仅新增ES4/ES5；v1、v2、v3文件字节保留。新增站沿既有缺省三段报价：放电420/450/480元/MWh，充电300/280/260元/MWh，各覆盖0–150MW；SOC申报保持上述0.1/0.9/0.5。新增默认报价不冒充基于真实成本生成的实际申报。

固定成本档案增加ES4/ES5各25元/放电MWh退化成本，来源为现有按储能类型生成的研究模板。报价成本依据增加replacement_energy=250、degradation=25、reservation=410，亦为既有模板假设，不是实测，不据容量将单位电量成本成倍提高。已有ES1/ES2/ES3不同历史成本保持不变。充电现金已包含在净结算，不重复扣购电费。

通用机组编辑、报价下拉、成本预览、网络资源表、SOC/备用/结算/利润应自动包含新增ID。新增回归将检查两站在页面可选择、成本预览只影响所选机组、不改变容量段和其他报价、不直接改历史文件。

旧场景复制仍保留原三站及原报价；从新默认创建的新场景才包含五站。已有名为“默认”的场景也不会被覆盖：网页通过“从新版默认配置新建场景（保留旧场景）”创建并切换，新旧摘要会显示各自电池MW/MWh；命令行使用仓库当前config则直接读取扩容输入。历史测试夹具已经明确保留旧新能源与旧规则，亦须明确保留ES1/ES2/ES3；新的默认容量用专门扩容测试及完整日C/D组验证，不能把历史golden静默变成新配置。

## 5. 实施后验收与风险披露

1. 校验总容量、节点存在、效率/SOC、报价完整性及成本覆盖；核对v4既有报价与v3逐字段等价，v1–v3哈希不变。
2. 回归新旧场景隔离、复制、页面选择、手动/成本报价、网络容量显示、结算主体及利润成本。
3. 由集成统一跑新水电备用约束下的丰水ID开启与枯水ID开启96段正式运行；与原装机组做同seed对照，不能把本次LP结果移植为新策略正式结果。
4. 每组披露执行段数、DA/ID/RT求解gap、备用缺额、失负荷/线路松弛、弃风光、每站充放电和循环利用、末SOC偏差、结算对账和运行耗时。
5. 新增储能不创造能量、不保证消除枯水晚峰备用不足；所有未覆盖的场景仍需单独检验。未经AC潮流、电压/无功、稳定性、设备寿命及投资测算，不称为实际工程可实施或经济最优方案。

筛查脚本：`scripts/check_storage_expansion.py`。筛查证据：`evidence/storage_expansion_20261106/screening.json`、`screening.csv`、`input_hashes.json`、`source_unchanged.json`。冻结筛查证据已收入本文同级`evidence/storage_expansion_20261106/`，仅对应扩容前筛查时的水电备用口径；新15分钟水量备用约束下完整日结果另行验收。

## 6. 局部实施核验

默认配置、报价、研究成本及 UI 相关局部回归151项通过（18.76秒），含两新增站的成本预览不写历史报价、旧场景复制不新增资源、v4既有15主体报价逐字段等于v3、容量/可用能量和成本匹配。原报价、已有场景及历史输出合计43个原有文件哈希未变；清单见 `evidence/storage_expansion_20261106/implementation_checks.json`。

追加跨场景、机组编辑及报价/成本恢复兼容组155项通过（181.96秒），与前组共306项独立用例通过。完整日志收入同一证据目录。新版默认入口摘要增加电池功率与额定能量，显示实际所选配置，不自动迁移旧场景；该展示补充后13项相关用例重跑通过（14.89秒，已在306项中，不重复计数）。

本补丁不改DA/ID/RT策略模型。历史SCUC夹具显式保留ES1/ES2/ES3及其原新能源组成；新默认五站由专门回归及后续完整日验收覆盖。以上局部结果不替代集成后的新水电备用约束及96段运行。
