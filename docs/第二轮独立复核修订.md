# 第二轮独立复核与修订方案

状态：基于已交付审阅候选的新一轮独立复核。前一轮源码、附件、四组全天及两组灵敏度结果保持原样；第二轮使用独立工作副本。尚未提交、合并或推送。本文件中模型部分先与项目Page同步，回读确认后实施；不能把上一轮测试计作本轮改动后的验收。

## 1. 已证实的问题与非模型修复

1. 显式外部报价：`main_full --bid-file ... --read-only-inputs` 在报价目录没有 `bids_v*.json` 时，`pipeline.prepare` 直接构造默认v1，未调用被替换的loader，v901外部报价被静默忽略。改为明确参数注入报价对象，不再修改模块全局loader；指定文件必须始终优先且校验失败时停止。外部对象在副本中校验/补齐，不能改写文件或调用方对象。外部版本与显式 `--bid-version` 冲突时明确拒绝，不能静默选一方。
2. 日前CLI：现有 `out_dir(exist_ok=True)` 可覆盖同名旧结果。应在求解前独占创建新目录，支持新tag并冻结实际输入；已有目录失败且保留原内容。所有使用同一输出助手的入口不得继续默许覆盖。
3. 应用停止：`run_app.sh stop` 仅凭PID发信号，PID复用会误杀无关进程。停止/重启前必须校验本次启动身份和本项目命令；身份缺失或不匹配时拒绝终止，测试仅使用自行启动的无害进程或替身。
4. 结果元数据：`meta.json` 为列表、null，或started类型异常可使全部运行记录列表崩溃。隔离损坏记录，不更改真实文件，不把损坏项伪装成完成；其他有效记录和历史结果保持可访问。
5. 验收脚本：`--render` 得到渲染异常或缺必要页签时仍返回验收通过和exit0。总验收必须同时满足数据检查和请求的渲染检查；异常、缺块、无法验证均失败，批次继续检查其余目录。
6. 结果页说明：固定“2小时/日前价值/日前带/日末约束保留”的旧文案与可配置窗口、日内实际来源和实时soft政策冲突。只依保存配置和逐资源证据说明，历史hard、缺字段旧档、日前来源、日内来源和回退分别呈现，不借当前默认配置解释历史。

7. 后台运行入口：显式 `run_scenario --run-dir` 指向旧完成目录时，会在读取冻结输入前改写旧meta；失败后旧summary与新失败meta混在一起。首次写入前只允许新目录或与本次场景/模式/请求匹配的UI新预留记录，持有该目录独占执行锁；旧done/failed/running、损坏身份和已有结果均拒绝，不触碰其内容。
8. 结果证据全集：RT线路删除一条支路的全部记录仍可显示“无阻塞”，截断阶段诊断JSON使结算页停止渲染，可选储能明细缺失使对比页崩溃。核对冻结网络的支路×执行时段全集；缺数据明确提示未知/损坏，不能把缺行当0或借当前网络填补。诊断或可选明细故障应隔离到相应部分，保留其他可核验结果，不伪造整页全部通过。

## 2. 梯级跨日前前史：保持既有物理假设的一致性修复

已证实：SCUC水量动态在上游来源时标小于0时，使用上游设备申报初始发电出库 `water_rate × init_units_on × init_p_unit`。水电软前瞻却在同一条件取0；旧hard回归包络也取0。合法示例下游lag=12、实时窗口[0,8)，剩余时段8–11各应到达初始240m³/s，漏计净来水为4×240×0.25×0.36=86.4万m³。这是现有公式前史不一致，不是引入新来水预测假设。

修正范围：

- 没有上游的电站继续没有上游来水；有上游且来源时标小于0时，软前瞻和旧hard包络均沿用SCUC已声明的初始发电出库，不添加未声明的初始弃水。
- 日内已执行时标继续读实际出库历史；尚未执行部分继续读本轮已选择的DA/ID参考，不以未来实际值替代预测，不恢复被关闭的硬末态。
- 逐窗口证据明确标识“日前之前初始出库”，与无上游、已执行历史、所选参考区分。完整精度独立审计按冻结设备参数重新计算，不让导出数组自证正确。
- 保留参考续程是有限成本偏好、不是全网/梯级可行证书的边界；原单库默认场景的物理模型与参数不变。
- 加入边界测试：无上游、来源时标−1/0、滞后超过当前窗口、跨窗已执行历史、DA/ID选择及失效回退；以真实SCUC前史表达式比对前瞻公式，核对86.4万m³差额和罚金量纲。

## 3. 统一时间网格的输入校验

合法数值但彼此冲突的配置 `dt_h=.25, realtime.interval_min=30, lookahead_h=2` 在value模式被接受，按interval计算4段后实际仅1小时，却声明2小时；只有two_hour_eq已有一致性检查。所有实时策略均需校验 `interval_min=60×dt_h`，前瞻时长及启用日内的滚动间隔必须是正的整段数，拒绝靠round静默缩短/延长窗口；当前实现每轮只执行首段，不能接受不支持的binding_periods。校验覆盖加载配置及CLI/程序化覆盖之后、构造滚动窗口之前。保留日末截断与短前缀研究，不将额外时标校验冒称已验证所有非15分钟业务规则。默认15分钟设置不变。
